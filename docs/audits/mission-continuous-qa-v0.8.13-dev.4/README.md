# 챕터 1~3 연속 검증용 플레이 기록

새 검증용 게임에서 챕터 1부터 3까지 실제 브라우저로 이어 플레이했습니다. 중간 저장을 불러오거나 비공개 상태를 수정하지 않았습니다. 0.8.13-dev.3 첫 실행 후 복귀 경계의 BB-011을 수정하고, 0.8.13-dev.4에서 새 게임으로 다시 완주했습니다.

각 실행은 공개 명령 260개, 명령 후 임무 알림 26묶음·32이벤트입니다. 초기 게임 생성 안내 1회는 별도로 기록합니다. 반복 실행과 DOM 필드 비교, 모델 계획, 스크린샷을 서로 다른 테스트 사례 수로 합산하지 않습니다. 첫 실행의 1·2번 행동은 개별 DOM 관찰이 없으며 최종 제품 내보내기에서 명령 수락을 확인했습니다. 36~37번과 132~133번은 동행 확인 1회가 두 엔진 명령을 커밋합니다.

- [결과](results.json): 실행별 수치, 알림 확인 후 남은 비용·보상·챕터 전환, BB-011 수정 전후, 실제 화면과 제한 범위
- [첫 실행 행동](runs/initial-dev3/browser-actions.json) / [알림](runs/initial-dev3/browser-notices.json)
- [수정 후 실행 행동](runs/recheck-dev4/browser-actions.json) / [알림](runs/recheck-dev4/browser-notices.json)
- [모델 기대값](model-expectations.json): 브라우저 증거와 구분한 경로 계획
- [SHA-256 목록](sha256-manifest.json): 보고서·공개 명령·스크린샷 파일의 바이트 해시

`node docs/audits/mission-continuous-qa-v0.8.13-dev.4/scripts/replay-continuous-qa.cjs`로 QA 설정과 실제 공개 명령을 엔진에서 다시 실행할 수 있습니다. 이 스크립트는 브라우저를 조작하지 않고 플레이 저장도 만들지 않습니다. 제품에서 내려받은 전체 저장은 로컬 작업 폴더와 다운로드 폴더에만 보존합니다.

검증 무기와 QA 소모품을 사용한 한 경로입니다. 모든 상호 배타적 임무 분기, 정규 장비 균형, 모든 화면 크기 또는 Unity Editor 실행을 검증했다는 뜻은 아닙니다.
