## 원본 그림과 atlas 검수

선택한 새 PNG 여섯 장을 원본 크기로 직접 열어 각 16포즈, 합계 **96개의 정적 원본 포즈**를 확인했습니다. 대기·걷기·공격·피격·쓰러짐에서 정체성·의복·저작 방향을 대조했고, 작은 팔의 연결이나 사체의 가림은 별도 원본 영역으로 확인했습니다. alpha/component 수치 검사는 이 직접 열람을 보조합니다.

런타임 PNG는 선택한 생성 결과의 바이트를 그대로 복사했습니다. 프레임 사각형·trim·발 기준·표시 크기·소유 영역은 atlas/manifest 메타데이터로 처리합니다. 각 프레임의 `clipRects`는 그 포즈에 속하는 포함 영역입니다. 큰 팔·무기 때문에 crop이 원래 셀을 넘더라도 다른 포즈의 조각을 함께 그리지 않도록 합니다. PNG를 단순 4×4 격자로 자르는 방식은 이 런타임 atlas 계약과 일치하지 않습니다.

원본 후보와 수동 등록에서 발견한 문제를 재현 예시와 함께 구분해 보관했습니다. 다음은 이미 교체한 후보의 예입니다. 이 반려 목록을 현재 게임 규칙 버그와 합산하지 않습니다.

합계 **9개의 실제 시나리오, 19개의 플레이 행동 명령**입니다. 실제 공개 내보내기 9개를 별도 정상 엔진에서 불러와 재생했고, 시작·기존 예상 종료·실제 종료·정책 반영 예상 종료 저장의 **정상 import 36회**를 확인했습니다. 준비 시점과 검사 시점의 규칙 엔진 SHA256도 동일했습니다.

대조 중 예상 준비의 차이를 확인했습니다. 원래 준비 helper는 `E.importSave`만 사용했고, 웹 앱의 `applyLoadedRuling`을 반영하지 않았습니다. 실제 UI는 불러오기 직후 각 시나리오에 **`APPLY_TILE_SPEED_RULING` 한 번**, 합계 **9개의 명시적 정책 채택 명령**을 기록합니다. 그래서 revision이 1 늘고 `tileSpeedRuling`이 `all-attacks`가 됩니다. 원래 예상 파일은 보존하고 이 정상 명령을 재생한 별도 예상 파일로 대조했습니다. 이를 게임 오류로 등록하거나 차이가 있는 규칙 필드를 무시하지 않았습니다.

공격 7개에서는 UI가 `itemIds: []`, `pullIds: []`, `rewardIds: []`를 명령에 추가합니다. 이 빈 선택 목록과 누락된 선택 목록을 명령 기록에서만 정규화했습니다. 그 결과 **9/9 전체 상태가 일치하고 실패 0**입니다. seed·rulesVersion·revision·phase·체력·손패·사용 슬롯·적 위치/체력/면·임무·전투·후속 선택·RNG·덱·이벤트를 생략하거나 변경하지 않았습니다. 정책 반영 뒤 공격 없는 두 파일은 바이트까지 동일하고, 나머지 일곱은 위 빈 인자 기록 차이가 있습니다.

공개 DOM의 actor **37개**에서 ID·논리 칸·skin을 대조했고 새 여섯 ID가 모두 일치했습니다. `presentationAttacks` 같은 누적 표시 카운터를 시나리오별 동작 수로 합산하지 않습니다. 원시 QA 저장·사용자 참고 사진·개인 플레이 저장은 이 감사 문서에 복사하거나 업로드하지 않습니다.

## 실제 화면 표본의 범위

정적 원본 96포즈와 실제 동작 화면은 다른 검증입니다. QA 전용 느린 재생과 정상 FPS gallery, 실제 지도 정착 화면을 시간 순서의 원본 스크린샷으로 확인했습니다. 짧은 공격·피격 표본이 이미 회복/대기에 도달한 경우에는 준비·타격 포즈를 모두 찍은 것으로 세지 않습니다. 저속 QA 사망 재생이 제품의 제거 시간보다 길어 마지막 자세를 놓친 표본은 정상 사망 표본으로 보완합니다.

이는 연속 영상의 모든 중간 렌더 프레임 검수나 실제 60fps 영상 분석이 아닙니다. 카메라 위 경계 밖의 머리/뿔을 PNG 원본 절단으로 기록하지 않고 전신 gallery·지도 전체보기와 구분합니다. 의복·갈기·사체에 자연스럽게 가려진 관절을 전부 드러난 것으로 판정하지 않습니다. 이번 공통 16포즈는 적마다 모든 인쇄 공격·능력에 별도의 고유 동작 시트를 만들었다는 뜻도 아닙니다.

기존 125영상의 남은 전프레임 검토는 사용자 선택으로 보류한 상태를 유지합니다. 이번 원본 96포즈와 새 9시나리오를 그 보류 범위의 완료로 합산하지 않습니다. 여성 환자 B면의 별도 정상 플레이 시작점은 확보하지 못했고, A/B 공통 그림 연결과 B면 실제 실행은 구분합니다.

## 최종 보스 크기와 별도 후속 검사

최종 보스 메타데이터는 `displayHeight: 400`, 지도 예약 영역은 타일의 `60×56%`입니다. 512 source의 여백을 제외한 대기 몸 높이는 기본 290픽셀 지도 타일에서 약 150.78픽셀이며, 일반 인간형 약 72.65픽셀의 2.07배입니다. `displayHeight`가 실제 몸 높이와 같은 값이라는 뜻은 아닙니다. 성직자 야수에만 renderer의 크기 상한 512를 적용하고 다른 actor의 상한 256을 유지합니다.

Gallery에서 공통 카메라 배율 2.1을 적용할 때 몸 높이는 보스 약 316픽셀, 보통 인간형 약 115픽셀입니다. 보스 미리보기 영역을 440픽셀로 넓히고 좁은 화면에서는 `min(2.1, viewportWidth/500)`으로 카메라를 줄입니다. 비교 대상도 같은 카메라 계수를 적용하므로 보스와 대상의 크기 비율을 유지합니다. 실제 규칙 칸이나 출현 마커의 위치는 표시 크기에 맞추어 변경하지 않습니다.

최종 크기로 **보스 2페이즈 공격 → 해결 한 번을 별도 재실행**했습니다. 정상 import 4회, 정책 채택 1개와 플레이 명령 2개를 확인했습니다. 마지막 실제 저장은 기존 2페이즈 실제 저장과 원시 바이트·SHA256 및 전체 규칙 상태까지 동일합니다. seed 90·rulesVersion 14·revision 331·플레이어 차례, 사냥꾼 체력 2와 보스 2페이즈 체력 6이 `tile-19:bottom`에서 유지됐습니다. 이 후속 검사를 원래 9시나리오·19명령·36 import·37 DOM 대조 수에 합산하지 않습니다.

## Unity 이식과 모델 교체에 남길 기준

기존 Unity exporter의 `assets` 재귀복사 조건에는 새 PNG 6개·atlas 6개·공통 manifest가 포함됩니다. 파일 경로·SHA256·trim·발 기준·표시 메타데이터를 보존할 수 있습니다. 이번 읽기 검토에서 exporter를 실행하거나 기존 생성물을 덮어쓴 것은 아닙니다.

**Unity의 공개 적 actor와 새 skin ID 연결은 차기 작업입니다.** 현재 `public-view.cjs`는 적의 ID·칸·체력·이름을 내보내며 새 `enemy-visuals.js` 연결은 아직 없습니다. ReferenceEngine export 목록에도 이 모듈이 없으므로 PNG 바이트 보존과 Unity 화면 연결을 구분합니다. 공개 schema·C# 계약·실제 Importer는 이번 웹 그림 작업에서 확장하지 않습니다.

다음 Importer는 개별 frame crop을 `spriteSourceSize`로 512 source에 복원하고, `clipRects` 소유 마스크·같은 발 원점·오른쪽 저작 방향·개별 표시 크기와 애니메이션 프레임/fps/반복을 읽어야 합니다. 공통 source의 발 기준은 `(256, 460)`입니다. Unity의 위쪽 Y 좌표계로 바꾸는 full-canvas pivot은 `(0.5, 1−460/512)`이며, trim 사각형의 아래 끝을 pivot으로 삼지 않습니다. PNG를 단순 4×4로 나누면 포즈가 셀을 넘는 부분과 소유 마스크를 잃습니다.

사냥꾼·적의 규칙 칸과 출현 마커는 모델 크기에 따라 바꾸지 않습니다. 표시 자리 보정은 save/domain에 쓰지 않고 같은 칸의 배치 우선순위와 선택 가능성을 유지합니다. 새 Unity 모델을 넣으면 동일 명령의 상태와 실제 접지·혼잡·공격 대상·후속 선택을 다시 확인합니다.

이 기록은 실제 Unity Editor 실행, 전체 C# 규칙 엔진, Unity 씬·Animator 구현 완료를 뜻하지 않습니다.
