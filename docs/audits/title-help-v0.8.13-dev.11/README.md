# 타이틀·처음 사냥 도움말 · 0.8.13-dev.11

2026-10-15. 첫 화면을 **블러드본 / BLOODBORNE** 타이틀로 만들고 **시작하기 · 불러오기 · 도움말**을 연결했습니다. 자동 저장이 있으면 일반 사냥과 검증 사냥의 이어하기가 따로 나타납니다. 이전 훈련 화면은 `training.html`로 보존했습니다. 타이틀은 게임 엔진을 실행하지 않고 저장의 존재만 확인합니다.

도움말은 `game-help.js` 한 곳에서 작성해 타이틀과 플레이 화면에 함께 표시합니다. 화면 읽기와 첫 턴6단계는 바로 보이며 카드·이동·전투·회피·임무·꿈·저장·용어·연습의9항목은 펼쳐 읽습니다. 본문은14–15px, 줄간격1.7입니다. 미공개 이야기와 미확정 프로젝트 재정을 공식 규칙으로 소개하지 않습니다.

## 시작·불러오기와 저장 보존

| 일반/검증 이어하기 | 요청한 모드의 저장만 기존 검증·명령 재생·정책 채택 경로로 가져옵니다. 손상된 저장을 다른 모드로 임의 대체하지 않습니다. |

## BB-035 · 늦은 파일이 새 진행을 덮어쓰는 경합

[Issue49](https://github.com/dfrpg98-jpg/bloodborne-solo/issues/49). **파일A(시드111)를 읽는 동안 진행B(시드222)를 선택하면, 뒤늦게 완료된 A가 B를 교체하고 자동 저장하던 문제**입니다. 이전 앱에도 있던 경합을 새 진입 경로 검토에서 발견했습니다.

수정 전 증거는 불변 커밋 `12c2f2b`의 정확한 파일 핸들러와 실제 엔진으로 만든 저장을 격리 메모리에서 사용한 [재현 기록](evidence/import-race-before.json)입니다. 최초 관찰 때 해시를 저장하지 않았으므로 이 불변 원본의 재실행 결과와 구분했습니다. 네이티브 파일 시스템을 느리게 조작한 브라우저 재현으로 세지 않습니다.

수정 후에는 읽기 요청 번호와 시작 시 상태가 그대로인 최신 결과만 채택합니다. 다른 파일·이어하기·새 사냥 준비/확정/취소·불러오기 취소는 이전 요청을 무효화합니다. 읽는 동안 실제 게임 상태가 바뀌어도 이전 파일을 적용하지 않으며 오래된 실패도 새 진행에 오류를 표시하지 않습니다. File 객체 확보 직후 입력을 비워 취소 뒤 같은 파일도 다시 선택할 수 있습니다.

지연 읽기5조건은 복원 뒤 늦은 성공, 두 파일의 역순 완료, 새 사냥 확정 뒤 늦은 실패, 게임 행동 뒤 늦은 성공, 준비 창의 네이티브 취소입니다. 독립 검토의 Escape 경로 누락과 같은 파일 재선택 문제도 보완했습니다. [수정 후 검토](evidence/review-after.json).
