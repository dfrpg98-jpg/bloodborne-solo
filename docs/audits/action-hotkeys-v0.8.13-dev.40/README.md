# 행동 Q·E·Z·C · dev.40

이동 선택·마치기를 Q로 바꾸고, 꿈으로 이동 E·장치무기 변형 Z·적 공격하기 C를 실제 행동 버튼의 클릭 경로에 연결했습니다. 손패가 먼저 선택되어 있어도 hunter 단계의 Q는 이동 행동의 확인 화면을 엽니다. 이동 중 Q는 활성화된 이동 마치기 버튼을 누릅니다. 숫자패드 5는 기존과 같이 이동 선언만 담당합니다.

기존 사용자 게임과 저장이 분리된 `127.0.0.1:8891`에서 공식 새 사냥 UI로 실제 지도 전투 연습·교단의 종복·중앙 등불·장송의 칼날을 준비했습니다. CUA의 실제 키 입력으로 아래 동작을 확인했습니다. 엔진 내부 상태 주입이나 개인 저장 접근은 하지 않았습니다.

- Q/E/Z/C로 각 행동 선택, 손패 선택 전 비활성 ‘행동하기’의 Space 안내 유지, Esc로 비용 없이 취소
- 대상이 없는 C 무시, 선택된 공격 가능 적이 있으면 C로 공격 선택
- 다른 행동을 선택 중일 때 비활성 행동 키 무시
- 손패 선택 후 Backspace 취소, Space 이동 확정, 첫 칸 진입 후 Q 마치기
- 이동 선언·이동 중 M 무실행, 첫 칸 진입 전 비활성 이동 마치기의 Q 무실행

이동 비용은 원래 규칙대로 첫 칸 진입 때 소모됩니다. 실제 기록에서도 Space로 이동 선언한 직후 손패는 3장, 첫 칸 진입 후에는 2장입니다. 이 동작을 단축키 변경으로 바꾸지 않았습니다.

2035×1252, 1231×1252, 1280×720, 872×1252, 800×1252의 실제 적용된 viewport 크기를 읽어 확인했습니다. 네 라벨이 모두 `white-space:nowrap`로 각 버튼 너비 안에 표시되고, 우측 패널과 하단의 바닥 차이는 0px입니다. 첫 네 화면의 하단은 209px, 좁은 800px 화면은 기존 260px입니다. 임시 화면 크기는 검증 후 복원했습니다. 사용자 게임은 진행을 유지해 dev.40으로 다시 열었습니다.

[verification.json](verification.json)에 실제 키 입력 20단계, 화면별 라벨 경계와 제품 해시를 남겼습니다. 원본 캡처는 Git에서 제외한 `test-results/action-shortcuts-dev40/`에 있습니다. 단위 검사는 `hunter-action-hotkeys-dev40.test.cjs`의 8개와 기존 키보드·손패·숫자패드·Space·도움말을 포함한 관련 76개가 통과했습니다. 키 반복, 수정키, 입력란, 열린/최소화 창, 한글 물리키 및 숫자패드 분리는 단위 검사 범위로 구분합니다.
