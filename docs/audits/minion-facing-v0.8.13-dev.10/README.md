# 야수 사냥 하인 방향 재점검 · 0.8.13-dev.10

2026-10-15 재점검과 수정 검증 기록입니다. 하인의 왼쪽·오른쪽 방향이 어색하다는 보고를 받고 현재 원본 16자세와 렌더러의 방향 변경을 따로 점검했습니다. **확인된 렌더러 오류는 왼쪽을 보던 캐릭터가 수직 이동하거나 X좌표가 같은 대상을 공격할 때 오른쪽으로 돌아가는 문제입니다.** dev.10 수정 후에는 새 수평 방향이 없으면 기존 방향을 유지합니다. 연결 이슈는 [Issue47](https://github.com/dfrpg98-jpg/bloodborne-solo/issues/47)입니다.

원본 그림에서 특정 자세만 좌우가 뒤집혔다거나 벽돌을 쥔 팔이 바뀌었다는 뚜렷한 증거는 찾지 못했습니다. 다만 자세 사이에 몸통 각도가 달라져 방향이 바뀐 것처럼 보일 수 있습니다. 이번 수정을 원본의 모든 동작이 자연스럽다는 판정으로 해석하지 않습니다. 사용자가 본 모든 어색함의 원인이 이번 렌더러 오류 하나라고 확정한 것도 아닙니다.

## 현재 원본 16자세의 관찰

기존 승인 기록을 근거로 삼지 않고 현재 `huntsmans-minion.png`를 원본 크기로 직접 열었습니다. 얼굴·코의 방향, 가슴과 골반의 노출 방향, 어깨에서 벽돌을 쥔 손까지 이어지는 팔을 함께 보았습니다. 자세 번호는 대기 0–3, 걷기 4–7, 공격 8–11, 피격 12–13, 쓰러짐 14–15입니다.

| 자세 | 직접 확인한 범위 |
|---|---|
| 대기 0–3 | 얼굴과 코가 오른쪽을 향합니다. 가슴과 허리 앞면이 보이고 화면 왼쪽의 가까운 팔이 벽돌을 듭니다. 2번은 얼굴이 조금 더 옆모습에 가깝습니다. |
| 걷기 4–7 | 다리의 보폭이 바뀌어도 얼굴·몸통은 오른쪽에 치우친 같은 방향을 유지합니다. 벽돌을 든 가까운 팔과 반대편 빈손이 서로 바뀌는 모습은 확인되지 않았습니다. |
| 공격 8–9 | 가슴 앞면이 보이는 상태에서 화면 왼쪽의 벽돌 팔이 머리 위로 올라갑니다. 얼굴은 계속 오른쪽을 향합니다. |
| 공격 10 | 가슴이 거의 보이지 않는 구부정한 옆모습으로 몸통 각도가 크게 바뀝니다. 코는 오른쪽을 향하며, 가까운 어깨의 붕대 소매가 몸 앞을 가로질러 화면 오른쪽의 벽돌 손으로 이어집니다. 벽돌의 화면상 위치가 바뀐 것을 팔 교체로 단정할 근거는 부족합니다. |
| 공격 11 | 가슴 앞면이 보이는 대기와 비슷한 자세로 돌아오며 벽돌도 화면 왼쪽 아래로 돌아옵니다. |
| 피격 12–13 | 12번은 머리를 위·뒤로 젖히고 가슴이 거의 정면으로 열립니다. 머리의 위치만 보면 왼쪽 회전처럼 느낄 수 있지만 얼굴은 위·오른쪽으로 읽히며 벽돌 팔도 같은 쪽에 남습니다. 위로 젖힌 얼굴의 정확한 좌우 각도는 다른 자세보다 판단이 어렵습니다. 13번은 오른쪽을 보는 회복 자세입니다. |
| 쓰러짐 14–15 | 얼굴과 코는 몸의 오른쪽 앞에 있고 다리는 뒤·왼쪽으로 남습니다. 가까운 붕대 팔이 앞의 벽돌로 이어집니다. 두 손이 벽돌 근처에 모여 어느 손이 단독으로 쥐는지는 다른 자세보다 불명확합니다. |

가장 큰 시각적 차이는 **공격 9→10→11**의 몸통 회전과 빠른 회복입니다. 피격 12의 머리 젖힘과 거의 정면인 가슴도 방향 판단을 어렵게 만듭니다. 이 관찰만으로 10번이나 12번만 수평 반전하면 원래 오른쪽을 향하던 얼굴과 팔 연결까지 반대로 바뀔 수 있으므로, 선택적 프레임 반전을 이번 해결책으로 사용하지 않았습니다.

벽돌 팔은 대기 자세의 가슴을 기준으로 해부학적 오른팔로 읽힙니다. 같은 팔이 유지된다는 판단의 확실성은 비교적 높지만, 쓰러진 자세에서 두 손의 역할까지 모두 명확하다고 주장하지 않습니다. 원본에 단순 좌우 반전 자세가 없다는 판단과 모든 관절·시점이 자연스럽다는 판단은 구분합니다.

점검한 PNG의 SHA256은 `DCCACB4A1CEEA110B7AD6F65ACA94A21366CB9D2C50EB463239E832AF6DC736B`입니다. 이번 수정에서는 이 PNG와 `huntsmans-minion.atlas.json`을 변경하지 않았고 ImageGen 호출이나 새 에셋 생성도 하지 않았습니다. 개별 자세의 관찰과 판단 범위는 [원본 점검 기록](evidence/source-review.json)에 남겼습니다.

## 확인된 렌더러 오류와 수정

기존 `hunt-presentation.js`는 이동 때 `after.x < before.x`, 공격 때 `to.x < from.x`를 그대로 수평 반전 값으로 사용했습니다. X좌표가 같으면 두 비교가 모두 `false`가 되어, 이미 왼쪽을 보던 캐릭터도 오른쪽으로 돌아갔습니다. 수직 이동은 새 좌우 방향을 주지 않으며, 위·아래에 있는 대상에 대한 공격도 마찬가지입니다.

수정한 공통 함수는 두 X좌표가 유효한 수이고 서로 다를 때만 방향을 바꿉니다. 왼쪽 이동·대상은 왼쪽으로, 오른쪽 이동·대상은 오른쪽으로 돌고, 같은 X좌표에서는 기존 방향을 유지합니다. 이동과 공격의 두 경로에 같은 기준을 적용했습니다. 이 방향 처리는 하인 전용 그림의 변경이 아닌 공통 렌더러 수정입니다.

| 재현 조건 | 수정 전 | 수정 후 |
|---|---|---|
| 왼쪽을 본 뒤 같은 X좌표에서 위·아래로 걷기 | 걷기 시작에 오른쪽으로 바뀌고 대기 복귀 뒤에도 유지 | 걷기와 대기 복귀 모두 왼쪽 유지 |
| 왼쪽을 본 뒤 같은 X좌표의 대상을 공격 | 공격 시작에 오른쪽으로 바뀌고 회복 뒤에도 유지 | 공격과 회복 모두 왼쪽 유지 |
| 오른쪽을 본 상태의 같은 두 조건 | 오른쪽 유지 | 오른쪽 유지 |
| 좌우로 실제 이동하거나 반대쪽 대상을 공격 | 해당 수평 방향으로 회전 | 해당 수평 방향으로 회전 |

단순히 공격·피격·쓰러짐 프레임을 바꾸거나, 카메라·선택 표시를 갱신하는 것만으로 방향이 바뀌는 현상은 이 조사에서 재현되지 않았습니다. 새 회귀 검사는 실제 배포 하인 manifest와 atlas를 사용하며, 왼쪽·오른쪽 방향에서 소유 영역 마스크도 그림과 함께 반전되고 같은 위치를 유지하는지 확인합니다.

## 변경 범위와 개발본 적용 상태

기준 커밋 `2c98d0f5e6c5523bb0a03ea323cda7b5369c989a`와 대조한 [변경 범위 기록](evidence/change-scope.json)에서 하인 PNG·atlas·manifest, 전체 에셋, 캠페인/구성요소 데이터, 규칙 엔진과 Unity 포트는 그대로입니다. 방향 표시 수정은 판정·비용·논리 칸/마커·저장 형식·공개 schema를 바꾸지 않습니다. 원시 플레이어 저장을 복사하지 않았고 QA 미리보기는 플레이어 저장소를 사용하지 않았습니다. 실제 개인 플레이 화면의 저장 바이트가 적용 전후 같다는 검증은 이번 미리보기의 완료 범위가 아닙니다.

[Issue47](https://github.com/dfrpg98-jpg/bloodborne-solo/issues/47)의 방향 오류에 대한 수정과 위 로컬 검사는 완료했습니다. 데스크톱에서는 실행 중인 제품을 두 번 교체하지 않도록 차기 타이틀/도움말 빌드에 이 수정을 함께 포함할 예정입니다. **실행 중인 데스크톱 개발본 적용은 담당 root의 최종 적용 기록 대기 상태입니다.** 제품 커밋·배포·설치/HTTP 일치·실제 접속 화면과 기존 상태 유지 결과는 담당자가 확인한 뒤 별도로 기록합니다. 이 감사의 로컬 검사와 11장 QA 표본을 개발본 적용 완료로 간주하지 않습니다.
