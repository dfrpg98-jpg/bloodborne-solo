손패2장에서도 카드 한 줄이 표시 영역보다 높아 생기던 스크롤을 수정했습니다. [BB-029](../../bugs.md#bb-029--손패-한-줄이-패널보다-높아-두-장에도-스크롤이-생김), [Issue #38](https://github.com/dfrpg98-jpg/bloodborne-solo/issues/38)로 관리합니다. 게임 규칙, 카드 선택 명령이나 무기 슬롯을 변경한 작업은 아닙니다.

## 소스와 실제 확인 방법

- 수정 전: `4cbdef417c9810e3c558b78c3a6a8aae970a9ec7`.
- 수정 제품: `08d6405178111a11fe437309f4b7563fae84bea2` · `fix: fit one hand row within the loadout panel (#38)`.
- 실제 확인 주소: `http://127.0.0.1:8786/bloodborne-solo/hunt.html`. 로컬 제품 두 파일을 동기화한 뒤 새 서버에서 확인했습니다.
- 정상 `E.create/E.dispatch` 명령으로 준비한 검증용 저장을 제품의 공개 파일 불러오기로 가져와, 실제 인앱 브라우저의 카드 표시와 클릭을 확인했습니다. DOM 조회는 읽기 전용입니다. 정상 명령 모델은 준비 근거이며 실제 이동·전투·캠페인 완주 증거가 아닙니다.
- 실제 수정 후 확인은 기본1280×720의2~7장, 좁은848×1252의2·3·4장, 정상 획득한 긴 효과 카드가 포함된2장으로 총10상태입니다. 공개 JSON에 `finalBasicTwoCards`로 보존한 마지막2장 재확인은 별도의11번째 구성으로 합산하지 않습니다.

## 재현 예시와 원인

1280×720의 기본 지구력·기술2장을 표시하면 수정 전 카드 높이176px와 격자 세로 여백8px를 합쳐184px를 차지했습니다. 손패 표시 높이는 반올림153px(원래 측정152.61px)이므로 두 장만 있어도 한 줄 전체를 보려면 스크롤이 필요했습니다. 전체 손패 패널238px와 그 안의 제목·안내·덱 수 영역을 제외한 실제 카드 영역을 구분합니다.

848×1252에서는 손패 컨테이너가245px 이하의1열 조건에 들어가 두 장이 세로로 쌓였습니다. 이때 표시175px에 비해 콘텐츠가368px였습니다. 이 수정 전 근거는 실제 브라우저의 DOM 측정값입니다. 저장된 수정 전848px JPEG는848×477 부분 화면이며 손패가 찍히지 않았으므로 사진만으로 이 수치를 확인할 수 없습니다. 수정 후848px는 손패 사진과 DOM 모두를 보존했으며, 이를848px 사진 전후 대조라고 표현하지 않습니다.

`hunt.css`에는 초기 하단190px 선언과 뒤의 덮어쓰기 규칙이 모두 있습니다. 최종 기본 하단값은260px이며1280×720에는 별도의238px 규칙이 적용됩니다. 초기190px를 실제 최종 높이라고 설명하지 않습니다.

## 변경한 범위

제품 변경은 `hunt-hand-feedback.css`, `hunt.html` 두 파일입니다.

- 모든 카드 수에서 카드·격자 행 높이를136px로 통일합니다. 카드 수가 늘어나도 크기나 글자를 축소하지 않습니다.
- 격자 세로 여백은8→6px, 카드 내부 여백은10px/8px→8px/7px, 내용 간격은8→6px로 조정합니다. 제목16px·효과13px는 그대로입니다.
- 손패 컨테이너370px 이하의2열은 유지하고,1열 전환 기준만245→220px로 조정합니다. 매우 좁은 화면에서는 두 장도 여러 행이 될 수 있습니다.
- 너비801px 이상·높이721px 이상에서는 상단132px·트랙24px를 유지하며 하단228px를 확보합니다. 높이720px 이하의 기존238px 배치와 모바일의 별도 행 높이는 유지합니다.
- 카드의 내부 `overflow-y:auto`와 선택 강조를 유지합니다. 무기 슬롯 스타일·JavaScript·엔진·규칙·저장 명령은 변경하지 않습니다.
- 스타일 캐시 키를 `94063a9e6a83`에서 `66350354029f`로 갱신합니다.

손패4장 이상에서 안내 문구를 숨기는 기존 `hunt.css` 규칙은 유지했습니다. `.hand-panel:has(.stat-card:nth-child(4)) #cardHint`의 우선순위(1,4,0)가 손패 파일의 표시 규칙(1,2,0)보다 높으므로4장부터 표시 영역이 더 커집니다. 이는 카드 축소가 아니며, 수정 후 기본 화면에서2·3장은 표시153px,4장 이상은178px인 이유입니다.
