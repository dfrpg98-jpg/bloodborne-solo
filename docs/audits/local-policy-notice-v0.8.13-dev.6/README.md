# BB-028 · 정책 채택과 함께 뜬 임무 알림의 이전 면제 설명

클라우드 반환본 `33c236767d94ea5efa4c75bf1330e41721e91747`을 로컬에서 독립 검토한 결과, **속도 감소를 이미 적용한 저장과 적 상세에 맞지 않는 면제 설명이 새 임무 알림에 남는 문제**를 발견했습니다. 정상 명령과 실제 앱 핸들러로 재현한 뒤 로컬 인앱 브라우저의 제품 컨트롤로 수정 전과 수정 후를 확인했습니다. [Issue #36](https://github.com/dfrpg98-jpg/bloodborne-solo/issues/36)에서 수정본과 검토 상태를 관리합니다. 사진 전용 검사 패턴을 제외한 최종 Node 전체CI도2669개 통과했습니다.

## 재현 경로와 실제 문제

`E.create(90,"beast-claw",0,null,"hunter-pistol","center",{campaign:true,rulesVersion:14,qa:{preset:"custom",startRewards:[],startConsumables:[]}})`에서 시작합니다. QA 지급은 없고, 기존 정상 명령 파일 `tests/fixtures/weapon-campaign-completion/beast-claw-0.json`의 `slice(0,110)`을 재생합니다. 인덱스64의 `MISSION_CHOICE:attack`만 다른 합법적 선택 `release`로 바꿉니다. 상태 필드·손패·체력·적을 조립하지 않습니다. 110개 명령의 결과는 정확한 내보내기·다시 불러오기 대조를 통과합니다.

준비된 체크포인트는 챕터2의 예배당 위 칸에서 무기 처치 효과의 이동력1이 남은 상태입니다. `move.source`는 `weapon`이고 `weaponAfter`에는 원래 전투로 돌아갈 단계가 보존되어 있습니다. 예전 저장을 검증한 뒤 진행 중인 반응을 마칠 때까지 정책을 보류하는 동작은 정상입니다.

수정 전 포트8793에서 이 파일을 제품 UI로 불러오고 **여기서 이동 마치기**를 누르면, 임무31번이 공개되며 정책 채택도 정상 기록됩니다. 저장은 `tileSpeedRuling:"all-attacks"`이고 환자의 예배당 감속은1이지만, 새 알림은 **“기존 저장 판정 · 이 적은 타일의 속도 감소를 받지 않습니다.”**라고 설명합니다. [수정 전 알림](evidence/notice-before.jpg)과 [수정 전 상세 표본](evidence/detail-before.jpg)을 보존했습니다.

BB-025의 속도 판정 수정이 실패한 사례가 아닙니다. 임무31이 지정하는 갈가리 찢기의 **기본 속도3·피해3·기절**은 임무의 원문 수치입니다. 예배당에서 실제 공격은 속도 -1을 받아 **속도2·피해3·기절**로 적용됩니다. 알림의 기본 수치3은 유지하며, 사실과 다른 면제 설명만 수정합니다.

## 최소 수정과 회귀 보호

`commitCommands`는 기존 명령 묶음을 전부 처리하고 관측 단계의 알림을 만든 뒤, 이전과 동일한 시점에 안전한 타일 정책을 채택합니다. 새 표시 모듈은 정책 채택 전후의 이미 공개된 적 효과를 비교하여 **이번 알림에 실제 포함된 폐기된 효과 문자열만 제거**합니다. 원래 명령·정책 시점·판정·비용·RNG는 유지합니다.

모든 관측 중간 상태를 최종 상태로 바꾸면 이전 단계의 임무나 동행·진입·보상 결과를 잘못 설명할 수 있습니다. 이번 수정은 그런 교체를 하지 않습니다. 다른 임무의 알림 내용과 객체, 기존 기록, 알림 식별자를 보존하고 새로운 알림을 추가로 만들지 않습니다. 가져오기만으로 지난 임무 알림을 재생하지 않으며, 공개된 예전 공격이 남아 있으면 여전히 기존 수치로 마친 뒤 안전한 단계에서 정책을 채택합니다.

회귀 파일은 `tests/mission-notice-policy-adoption.test.cjs`입니다. 실제 비동기 파일 불러오기 핸들러와 이동 종료 핸들러를 실행하고, 정상 엔진 명령으로 만든 결과와 대조합니다. 이것은 DOM 테스트 하네스이며 실제 브라우저 증거와 구분합니다.

- 수정 전 새 재현 검사: **1개 실패**. 면제 문구가 남는 기대 불일치를 확인했습니다.
- 수정 후 신규4개와 관련 기존 검사: **26개 통과·0개 실패**. 수동 알림 재열람, 다른 일괄 알림·이전 기록 보존, 미공개 임무 알림 생성 금지, 예전 공격의 정책 보류를 포함합니다.
- 앞선 독립 검토의 관련36개 검사는 기존 회귀 범위입니다. 26개와 중복되는 항목이 있으므로 두 수치를 합산하지 않습니다.
- **최종 로컬 Node 전체CI: 2669개 통과, 실패·취소·스킵0개**. `node scripts/test-ci.cjs`, Node v24.19.0, 런타임0.8.13-dev.6,428.541초, 종료 코드0입니다. 신규 회귀 파일도 검사 목록에 포함됐습니다. 위 개별26개 결과를 전체2669개에 다시 합산하지 않습니다.
- CI runner는 원본 사진 전용4개 테스트 이름 패턴을 제외합니다. `skipped:0`은 runner가 실행한 검사의 보고값이며, 이 제외된 원문 사진 대조까지 실행했다는 뜻이 아닙니다. 모든 원문 사진·모든 무기 애니메이션 프레임·정규 구성품 캠페인의 전수 브라우저 확인으로 확대하지 않습니다. [원본 CI 결과 JSON](evidence/local-ci.json)에 전체 실행 명령, 테스트 파일 목록, 제외한4개 이름 패턴과 실제 집계를 보존합니다.

## 실제 로컬 브라우저 재검증과 다음 행동

수정 후 포트8794에서 같은 정상 체크포인트를 제품 UI로 **한 번만** 불러왔습니다. 이동 종료로 뜬 알림에서 면제 문구가 제거된 것을 확인하고, 공개 적 상세와 전투의 감속 표시를 대조했습니다. 화면·모델 결과를 성공으로 바꾸기 위해 중간 저장을 다시 불러오지 않았습니다.

알림 확인 뒤 다음11개 정상 명령을 전부 실제 컨트롤로 실행했습니다. `REFILL`은 정상 라운드 손패 보충이며 검증용 소모품 보충이 아닙니다. 알림 확인은 게임 명령이나 비용으로 세지 않습니다.

```js
[
  {type:"END_TURN"},
  {type:"NO_ATTACK"},
  {type:"RESOLVE"},
  {type:"REFILL"},
  {type:"MOVE",cardId:"card-12"},
  {type:"STEP",node:"tile-17:lower-left"},
  {type:"STOP_MOVE"},
  {type:"FIREARM_ENTRY",accept:false},
  {type:"ATTACK",cardId:"card-7",slot:0,enemyId:"mission-patient"},
  {type:"RESOLVE"},
  {type:"STUN_DISCARD",cardId:"card-10"}
]
```

환자의 첫 발톱 가르기(적용 속도1·피해2)를 받아 체력6→4, 정상 손패 보충으로 카드3장을 갖습니다. 활력 카드로 예배당 왼쪽 아래 칸에 이동한 뒤 추격한 환자에 대한 장총 진입 반응을 거절합니다. 근력 카드의 속도3·피해2 공격으로 환자 체력3→1, 환자의 갈가리 찢기(적용 속도2·피해3·기절)로 플레이어 체력4→1이 됩니다. 남은 활력 카드를 기절 비용으로 버리고 플레이어 차례로 정상 복귀합니다.

최종 결과는 라운드2, 플레이어 체력1·손패0, 환자 체력1, `tile-17:lower-left`, 미해결 이동·전투·무기 후속 없음입니다. 페이지 콘솔 오류는 실제 브라우저 도구에서0개를 확인했습니다. 마지막 제품 **저장 내보내기**를 정상 엔진으로 정확히 다시 불러오고, 예상 정상 명령 결과와 게임 상태를 대조했습니다. 게임 상태 대조에서는 UI가 선택적 빈 배열을 기록하는 차이 때문에 `commands` 필드만 제외했으며, 실제 명령 유형·순서는 별도 대조하고 실제 내보내기의 모든 명령·인자 재생 일치는 검증했습니다. 공개 결과는 [actual-policy-notice-local.json](evidence/actual-policy-notice-local.json)에 있습니다.
