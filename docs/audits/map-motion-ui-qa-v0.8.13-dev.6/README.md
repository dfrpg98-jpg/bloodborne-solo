# 지도 이동·변형·전투 검증 — 0.8.13-dev.6

검증용 플레이모드에서 정규 장치무기 15종의 두 형태, 총 30개 프로필을 실제 브라우저로 확인했다. 이 기록은 **지도 움직임 검증 배치**의 결과다. 이후 추가한 타일 정보·이동 패드·손패·화기·전투 UI에 대한 사용자 피드백 1–12의 실제 브라우저 검증은 아직 별도 진행이 필요하다. 아래 중간 CI도 그 UI 작업 이전 결과이며 최종 CI로 취급하지 않는다.

## 실제 브라우저에서 확인한 범위

엔진이 합법적인 검증용 시작 옵션과 명령으로 만든 체크포인트를 공개된 불러오기 UI로 가져온 뒤, 브라우저에서 `STEP`으로 위 칸 이동 → `STOP_MOVE`로 추격 처리 → 검증 소모품으로 손패 보충 → 무기 변형 두 번 → 손패·슬롯·적 선택 → `ATTACK/RESOLVE`를 진행했다. 초기 준비는 엔진 모델이며, 이어지는 클릭·공개 DOM·화면 사진은 실제 브라우저 관찰이다. 하나의 사냥을 처음부터 끝까지 이어서 완주한 기록은 아니다.

[browser-results.json](browser-results.json)에 30개 프로필의 단계별 공개 DOM, 최종 스냅샷, 수집한 콘솔 메시지가 있다. 마지막 누적 표시값은 이동 62회·공격 60회·발사 0회이며, Phaser 4.2.1, 캐릭터 `ready`, 움직임 `full` 상태였다. 수집한 콘솔 메시지는 0개다. 표식 `complete`는 이 검증 배치의 지정 단계 실행을 뜻하며 캠페인 완수를 뜻하지 않는다.

말뚝박이 두 번째 형태의 필수 밀치기와 이질적인 루드비히의 성검 두 번째 형태의 무료 변형 후속 선택까지 처리했다. **루드비히의 성검 첫 번째 형태는 무료 무기 변형 선택 화면까지 확인했으며, 이 배치에서 해당 선택을 끝낸 것으로 기록하지 않는다.** 후속 사진은 [말뚝박이](evidence/stake-driver-1-push-complete.jpg), [이질적인 루드비히의 성검](evidence/uncanny-1-free-transform.jpg)에 있다.

프로필마다 추격·다른 형태·전투 표본 사진 3장을 [browser](browser/)에 보관했다. [screenshot-index.json](screenshot-index.json)의 모든 파일은 원본 바이트와 SHA-256을 대조했다. 추격 사진 일부는 적이 이동하는 도중이고, 전투 사진은 특정 순간의 표본이다. 모든 중간 프레임을 촬영했다거나, 정지 사진만으로 순간이동이 전혀 없다고 판정하지 않는다.

## 확인한 배치 문제와 수정 후 근거

폐가의 아래쪽 입구 칸으로 야수 사냥 무리와 재앙의 야수를 함께 끌어오면, 기존 배치는 발 표식만 분리해 세 몸통이 겹쳤다. [수정 전](evidence/before-overlap-burial.jpg)과 [수정 후](evidence/after-overlap-burial.jpg)에서 몸통을 구별할 수 있게 된 변화가 보인다. 카메라 위치가 달라 직접 픽셀 차이를 계산한 비교는 아니다. 원래 관찰 세션의 시드도 추정하지 않는다.

독립적인 시드 13 검증 경로에서는 북쪽 탐험으로 폐가를 배치하고, 장송의 칼날을 변형한 뒤 두 적을 함께 끌어와 이 장면을 재현했다. [seed13-repack-model.json](fixtures/seed13-repack-model.json)에 초기 옵션·명령·공개 모델 요약을 기록했다. 새 배치는 공개된 몸통 범위를 고려하고 먼저 출현한 적의 인쇄 마커 자리를 보존한다. 칸 소속·게임 명령·출현 규칙은 변경하지 않는다.

처치 후에는 사망 몸통이 남는 동안 나머지 인물이 곧바로 그 위로 재배치되지 않도록 처리했다. [처치 직전](evidence/after-fix-before-kill.jpg), [순서 0](evidence/after-fix-kill-0.jpg)부터 [순서 7](evidence/after-fix-kill-7.jpg)까지 원본 사진을 함께 보관했다. 파일 번호는 촬영 순서이며 임의의 밀리초 간격이나 사진 기반 속도 수치를 붙이지 않았다. 앞쪽 사진의 시체·타격 포즈와 뒤쪽 사진의 자리 정리를 구분해 읽어야 한다. 시드가 확인되지 않은 최초 로컬 세션의 처치 사진도 [직전](evidence/burial-before-kill.jpg), [직후](evidence/burial-after-kill.jpg)에 있다.

대표 무기·추격·처치 시퀀스의 독립적인 사진 검토에서 추가적인 잘린 몸통이나 분리된 스프라이트 조각은 확인하지 못했다. 긴 무기의 공격 궤적과 팔·꼬리는 다른 인물의 영역을 지나갈 수 있다. 좁은 칸에 큰 몸통이 많거나 인쇄 마커가 고정된 경우에는 완전한 시각 분리를 보장할 수 없으며, 논리적인 칸이나 출현 자리를 바꿔 이를 숨기지 않는다. 이번 지도 수정에서 PNG·원본 타일 SVG는 변경하지 않았다.

## 재현 자료와 검증 상태

[model-inputs.json](fixtures/model-inputs.json)은 검증 초기 옵션·준비 명령·공개 모델 메타데이터다. 체크포인트를 만든 당시 버전은 dev.5, 위 브라우저 관찰 버전은 dev.6으로 구분했다. [generate-model.cjs](fixtures/generate-model.cjs)는 저장 파일을 쓰지 않고 `E.create/E.dispatch`와 메모리 내 내보내기·다시 불러오기 대조로 공개 모델만 출력한다. 저장소 루트에서 다음처럼 실행한다.

```text
node docs/audits/map-motion-ui-qa-v0.8.13-dev.6/fixtures/generate-model.cjs
```

실제 사용자 자동 저장이나 원시 QA 저장 파일은 이 폴더에 포함하지 않았다. 전체 원본 사진·시간 순서 자료와 로컬 체크포인트는 로컬 작업 폴더에 남아 있으며 Git으로 복사하지 않는다. 저장된 브라우저 결과는 공개 DOM 관찰이고, 모델의 예상 결과는 브라우저 관찰로 간주하지 않는다.

[intermediate-checks/motion-ci-before-feedback.json](intermediate-checks/motion-ci-before-feedback.json)과 [TAP 로그](intermediate-checks/motion-ci-before-feedback.tap)는 **UI 확장 이전 중간 검사**다. 2,610개 통과·0개 실패이며, 비공개 원본 사진 파일을 필요로 하는 4개 검사는 명시적으로 제외했다. UI 핸들러·배치 계약 테스트는 코드 경로 검증이며 실제 브라우저 렌더링 확인을 대체하지 않는다.

최종 CI 및 사용자 피드백 1–12의 실제 브라우저 확인·추가 결과는 이후 인계 작업에서 이 기록에 보완해야 한다. 현재 완료된 30개 무기 지도 움직임 배치와 아직 남은 새 UI 검증을 구분한다.
