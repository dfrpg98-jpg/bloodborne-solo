# 상황별 Q/E/Z/C와 행동 단계 분리 — 0.8.13-dev.41

기본 행동과 적 활성화에 대한 대응은 같은 단계에서 실행하지 않는다. 이 구분을 바탕으로 같은 키를 상황에 따라 다음 기존 버튼에 연결한다.

| 키 | 사냥꾼 차례 | 이동 중 | 적 활성화의 공격 선택 | 타일 배치 |
| --- | --- | --- | --- | --- |
| Q | 이동 | 이동 마치기 | 맞서 공격 | 0° |
| E | 꿈으로 이동 | — | 공격하지 않고 행동 공개 | 90° |
| Z | 장치무기 변형 | — | — | 180° |
| C | 선택한 적 공격 | — | — | 270° |

타일 회전은 활성 각도만 압축해 키에 배정하지 않는다. 0°가 막혀 있어도 Q는 0°에 대응하며 아무 행동도 실행하지 않는다. Space의 현재 선택 확정·타일 배치 기능은 별도로 유지한다.

## 검증 범위

`tests/action-phase-exclusivity-dev41.test.cjs`는 정상 캠페인의 기존 공개 명령을 그대로 재생한다. 두 경로는 seed 90, 시작 소모품 없음, 야수 사냥의 단총, 중앙 시작, rulesVersion 13이다. 첫 경로는 야수의 발톱 0면의 명령 351개, 둘째는 장송의 칼날 1면의 명령 325개다. 초기 상태를 각 한 번 포함해 678개 상태를 조사한다. 상태의 phase나 체력·적 배치 등을 임의로 바꾸지 않는다.

- `combat_choose`는 34번이며 모두 적 활성화에서 도달한다. 이동이나 꿈 행동이 동시에 활성화되는 경우는 0번이고, 진행 중인 이동 상태가 남은 경우도 0번이다.
- 기본 행동 모델은 `hunter` 이외 단계에서 네 행동을 잠근다. 엔진의 실제 `MOVE`/`DREAM`/`TRANSFORM`/`ATTACK` 명령도 사냥꾼 단계만 허용한다. 반대로 실제 `COUNTER`/`NO_ATTACK`은 `combat_choose`, `STOP_MOVE`는 `move`를 요구한다. 도달 가능한 상태에서 서로 다른 단계의 명령을 시도해 이 가드를 확인한다.
- 실제 컨트롤러를 메모리 DOM에서 실행한 정상 공격 선택 사례에서는 손패만 선택하면 맞서 공격이 비활성이고, 손패와 빈 슬롯을 모두 선택하면 활성화된다. 공격하지 않는 선택은 별도로 활성화되며 기본 이동·꿈 행동은 계속 비활성이다. 선택만으로 저장은 바뀌지 않는다.
- 두 경로에서 실제 도달한 사냥꾼 단계의 필수 보상 선택 3건에서는 기본 행동도 잠긴다. 단순히 단계 이름만으로 대응 키가 실행 가능하다고 판단하지 않는다.
- 성배 교단 예배당·오에돈 예배당·민가의 정상 공개 타일 배치 저장 3건을 별도로 재생한다. 네 기본 행동은 모델·컨트롤러·엔진 가드에서 모두 불가능하고, 기존 회전 버튼은 항상 0/90/180/270° 순서다. 첫 사례는 180°만, 나머지 둘은 0/90/180°가 가능하다. 비활성 각도도 고정 위치를 유지한다.

위 증거는 공개 명령 재생·엔진·행동 모델·메모리 DOM의 실제 컨트롤러 검증이다. 실제 운영체제의 키 입력을 했다는 증거는 아니며, 네이티브 브라우저 검증은 별도 기록과 구분한다. 사용자 브라우저 프로필과 저장은 사용하지 않는다. 기본 행동바의 숨김과 단축키 실행 검사는 별도 컨트롤러 검사에서 수행한다.

## 재생

```powershell
node --test tests/action-phase-exclusivity-dev41.test.cjs
```

제품 파일이 동결된 상태에서 보고서를 다시 만들려면 다음을 실행한다. 일반 CI 실행은 추적된 보고서를 덮어쓰지 않는다.

```powershell
$env:BB_WRITE_ACTION_PHASE_AUDIT = '1'
node --test tests/action-phase-exclusivity-dev41.test.cjs
Remove-Item Env:BB_WRITE_ACTION_PHASE_AUDIT
```

`verification.json`에는 경로별 도달 단계 집계, 선택 상태에 따른 컨트롤러 결과, 회전 옵션과 검사 전·후 제품 SHA-256을 기록한다. 생성한 플레이어 저장은 추적하지 않는다.

## 실제 화면과 키 입력

별도 origin 8892에서 정규 장비 전투 연습을 공식 설정으로 시작하고 공식 내보내기·불러오기로 같은 조우를 재현했다. 실제 Q 입력은 카드와 빈 슬롯을 선택했을 때만 맞서 공격을 실행했고, E는 카드를 쓰지 않고 적 행동만 공개했다. 선택 없는 Q와 조우의 Z/C는 상태를 바꾸지 않았다. 타일 공개 재생 저장 tile-17·tile-07을 공식 불러와 Q/E/Z 회전과 비활성 C, 180°만 허용될 때의 고정 키를 확인했다. 내보내기는 기존 불러오기 단계의 `APPLY_TILE_SPEED_RULING` 채택 한 건 외에는 원본과 같다. 회전 명령은 저장되지 않았으며 Space 배치 후 기본 행동바가 다시 보였다. Q로 행동 확인을 열면 바가 숨고 Escape 취소로 복구됐다. 실제 270° C 실행은 컨트롤러 검사로 확인했으며 네이티브 성공 사례로 합산하지 않는다.

사용자 origin 8860은 dev.41로 재로딩하고 읽기 전용 DOM 측정만 수행했다. 타일 배치의 네 비활성 버튼은 높이 0으로 사라지고 본문이 제목 바로 아래에 놓인다. 2035×1252에서도 확인한 뒤 임시 크기를 복원했다. 별도 검증 게임의 콘솔 경고·오류는 0이다. 전후 화면 폭을 고정하지 않았으므로 정확한 이동 픽셀 수는 비교하지 않는다. [실제 입력·화면 측정](actual-ui.json)은 공개 재생 증거와 구분하며 개인 저장은 포함하지 않는다. 캡처는 로컬 `test-results/contextual-keys-dev41/`에 보관한다.
