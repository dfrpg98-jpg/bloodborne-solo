# 선택 창을 유지하며 정보 살펴보기

- 모든 사냥 화면의 대화상자는 제목 부분을 끌어서 옮기거나 `최소화`·Escape로 접을 수 있다. 접힌 창은 화면 아래 복원 버튼으로 돌아온다. 제목에 초점을 두고 Alt+방향키로도 옮길 수 있다.
- 최소화는 확인·취소·보상 선택을 실행하지 않는다. 창의 `open` 상태와 입력값을 유지한다. 지도, 손패, 소모품과 장비의 정보는 계속 살펴볼 수 있다.
- 등록된 모든 정보창·선택창이 열리거나 최소화되어 있으면 실제 게임 명령은 차단한다. 슬롯 부착 창에서는 `REASSIGN_REWARD`만 허용한다. 정보 창이 추가로 열리거나 대기 창이 최소화되어도 이 제한은 유지된다.

## 연결 계약

`BBHuntWindowManager.install(document, { onBlocked })`는 기존 `showModal()` 호출을 해당 대화상자의 비모달 `show()`로 감싸며, 기존 확인·닫기 핸들러를 그대로 사용한다. 게임 상태나 저장 형식은 바꾸지 않는다. `sendCommands` 진입점은 `manager.canExecute(commands)`로 검사해야 한다. 직접 게임 명령을 실행하는 새 코드도 같은 진입점을 사용해야 한다.

`manager.register(dialog)`로 나중에 추가된 창을 등록할 수 있다. `refresh()`는 새 대화상자를 수집한다. `minimize`, `restore`에는 창 요소나 ID를 넘길 수 있다. `blockers()`는 최소화 여부와 관계없이 등록된 열린 창을 모두 반환한다.

예: 혈석 재배치 창을 최소화하고 인벤토리에서 소모품 설명을 읽는 것은 가능하다. 그 상태에서 소모품을 사용하거나 이동을 확정하면 명령을 보내지 않는다. 혈석의 슬롯을 바꾸거나 재배치를 마친 뒤에는 정상적으로 다음 행동을 실행한다.


최종 창 17개 검사 + 공개 성장 6개 + 셸 6개 = 관련 29개 검사 통과. 정보 메뉴 하나만 열린 경우의 불러오기·이어하기·새 사냥은 관리 응답으로 허용한다.
