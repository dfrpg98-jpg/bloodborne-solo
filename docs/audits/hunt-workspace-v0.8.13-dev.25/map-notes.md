# 목표·지도·선택 칸 정리

## 적용 내용

- 현재 목표는 지도 왼쪽 세로 패널로 옮기고, 선택한 칸 정보는 상단의 작은 요약 영역으로 옮긴다. 지도와 오른쪽 행동 패널의 키보드·읽기 순서도 화면 순서와 일치시킨다.
- 선택 칸 정보에는 그 칸의 적·토큰·상호작용과 타일의 지속 규칙을 표시한다. 같은 타일의 다른 칸은 나열하지 않는다.
- 현재 위치를 반복하는 문단을 없애고, `현재 위치` 버튼으로 해당 칸을 살펴볼 수 있게 한다. 대상이 없는 칸은 `비어있음`으로 표시한다.
- 현재 목표의 시체·생존자·임무 계몽 토큰은 해당 임무가 공개되어 진행 중일 때만 표시한다. 챕터 전체의 획득 계몽은 유지한다.
- 안개는 목표 문단 대신 해당 타일 가장자리의 회색 효과로 표시한다. 효과는 클릭을 막지 않으며 동작 줄이기 설정에서는 정지한다.
- 플레이어 차례의 중복 `대상 · 적 이름` 문단을 제거한다.

## 확인한 사례

1. 챕터 2 시작 시 공개된 18번 임무는 시체 두 종류만 표시한다. 관련 없는 진료소·예배당 생존자 0명과 3챕터 임무 토큰은 표시하지 않는다. 19번이 공개되면 시체 목표가 끝났으므로 해당 수치를 숨긴다.
2. 진료소 27/52번 임무 중에는 보유 생존자와 진료소 인원만 표시한다. 28번을 완료하면 숨긴다. 예배당 33번 임무는 보유 생존자와 예배당 인원을 표시하며, 34번을 완료하면 숨긴다. 이미 반대 피신처를 완수한 공개 이력도 반영한다.
3. 중앙 등불 타일의 왼쪽 칸을 선택하면 왼쪽 칸만 표시한다. 타일 전체의 순간이동 규칙은 남지만 중앙 칸의 등불 상호작용이 왼쪽 칸에 붙지 않는다.
4. 아직 공개하지 않은 타일 ID를 전달해도 타일 정보가 노출되지 않는다. 선택 칸 확인과 목표 필터링은 저장 상태를 변경하지 않는다.
5. 임무 적의 계몽 토큰이 마지막으로 소진되어도 최종 처치 전이면 `0`을 표시한다. 처음부터 계몽 토큰이 없는 적에게 불필요한 `계몽 토큰 0개`를 붙이지 않는다.

## 코드 경계

- `BBHuntMapControls.tileInfo(state, tileId, { node, selectedOnly: true })`: 해당 칸과 타일 규칙을 반환. 이전 두 인수 호출은 전체 칸 반환을 유지한다.
- `BBHuntMissionHUD.view(publicMissionView)`: 공개된 임무 정보만 읽고 `counters`, `tokens`, `targets`를 반환한다. 게임 규칙 및 위치·토큰 값을 변경하지 않는다.
- `hunt-workspace-layout.css`: 새 패널 위치와 안개 가장자리 효과. 기존 글꼴 크기를 확대하지 않는다.

검증: `node --test tests/mission-hud-map-workspace-v25.test.cjs` 7개 통과. 실제 화면 배치와 기존 UI 호출은 통합 후 별도 확인한다.

## 진행 상황·소모품·장비 탭

- 소모품과 장비는 오른쪽 인라인 탭으로 전환한다. 목록을 새로 그리거나 정보를 닫아도 선택한 탭을 유지한다.
- 실제 행동 성공 후 호출하는 `shell.showProgress()`에서 진행 상황으로 돌아간다. 목표와 임무, 사냥일지는 별도 정보 화면이다.
- 대상을 고르면 기존 지도 미리보기 콜백을 즉시 호출한다. 정보창을 열지 않아도 선택한 적을 확인할 수 있다.
- `shell.close()`는 정보창만 닫는다. 손실 확인을 취소하면 소모품/장비 탭과 선택한 대상을 그대로 복원한다.
- 마우스 외에도 방향키·Home·End로 세 탭을 전환할 수 있다.

단위·UI 확인: 독립 셸 6개, 행동 손실 6개, 임무 안내 6개, 대상 선택 24개 통과. 기존 HUD의 정보·이동·전투 조작 9개 통과. 351명령 전체 재생은 챕터 시작 후 혈석 재배치 창을 여는 신규 정책으로 `rewardTransformWindow`의 기대값 차이가 발생해 통합 측에 보고했다. 원본 기록 검증을 생략하거나 결과를 맞추기 위해 상태를 변경하지 않았다.
