## 검증

최종 자동 검사: **148개 파일의 3,124개 검사 모두 통과**(실패·취소 0). 일반 정보창 차단의 최종 변경까지 포함해 전체를 재실행했습니다. 기존 CI 정책으로 원본 사진을 요구하는 4개 검사는 제외합니다. [명령·실행별 결과·소스 해시](verification.json), [실제 브라우저 관찰](browser-checks.json). 최초 전체 실행에서 3,120개 중 7개는 옛 팝업/삭제된 준비 제목을 기대해 실패했습니다. 새 요구에 맞게 고친 3개 파일의 13개 검사는 모두 통과했으며, 실제 피해·비용·명령·저장 비교는 그대로 유지했습니다. 이 최초 실패를 게임 판정 오류 7건으로 세지 않습니다.

추가 근거:

- 실제 앱 핸들러: 모든 정보창도 열린/최소화 상태에서 게임 명령만 차단, 알림 → 혈석 창 → 재배치 → 다음 이동, 최소화 중 상태 변경 차단, 반복 복원, 소모품 1개 소비 후 진행 탭 복귀.

### 실제 브라우저

기존 플레이 저장과 분리한 `127.0.0.1:8829` 검증 모드에서 확인했습니다. 상태를 브라우저에 주입하거나 비공개 JS 변수를 고치지 않았습니다.

1. 새 검증 사냥에서 혈석 획득·슬롯 선택. CSS 실제 측정: 공격명 13px·수치 12px.
2. 새 임무 최소화 → 소모품/내 덱 열람 가능, 소모품 사용은 차단되고 수량 유지.
3. 임무 확인 → 혈석 장착 → QA 소모품 사용 1개 소비 → 진행 상황 탭 자동 복귀.
4. 꿈 진입·손패 보충 → 반대 면 귀환 → 파편을 1번에서 3번으로 이동.
5. 기존 검증 모드 공개 명령으로 만든 챕터 2·3 준비 저장을 제품의 불러오기로 열기 → 보관 파편 장착 → 반대 면 시작 → 임무 확인 → 자동 재배치.
6. 챕터 2 파편을 2번으로 이동 → 제품 내보내기 → 새로고침 복원. 내보낸 파일은 엔진에서 다시 읽어 동일 바이트로 재현.
7. 챕터 3 재배치 후 다음 MOVE가 정상적으로 이동력 2로 시작.
8. 소진된 단총의 하단 재준비 → 선택 손패 1장 소비 → 준비됨.
9. 실제 업그레이드 시장 선택 중 덱 구성 열람 → 구매·교체를 진행해 12장 덱 유지.
10. 같은 열기 버튼으로 최소화한 업그레이드 창 복원, 제목줄 키보드 이동, 안개 장식의 클릭 통과.
11. 목표와 임무/사냥일지 분리, 1280×720·2560×1400 가로 넘침 없음, 브라우저 오류 로그 없음.

공개 명령 준비는 `mission-continuous-qa-v0.8.13-dev.4`의 실제 검증 모드 이력에서 필요한 지점까지만 엔진으로 재생한 것입니다. 이번에 챕터 1~3 전체를 새로 브라우저 완주했다는 뜻은 아닙니다. 사용자 원래 파일 저장은 수정하지 않았습니다.
