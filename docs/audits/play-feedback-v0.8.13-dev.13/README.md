# dev.13 · 위치·전투 피드백과 혈석 슬롯 점검

개발본이며 릴리스·병합·태그를 만들지 않습니다. [Issue53](https://github.com/dfrpg98-jpg/bloodborne-solo/issues/53), [BB-037–042](../../bugs.md)에 각각 재현 예시를 기록합니다. 이번 작업에서 엔진 규칙과 저장 형식은 변경하지 않았습니다.

## 실제 브라우저 확인

Codex 인앱 브라우저의 별도 읽기 전용 로컬 검증 서버8811에서 UI로 진행했습니다. 일반 사냥 저장은 사용하지 않았습니다. 기록은 `native-results.json`과 원본 스크린샷으로 구분합니다.

1. 타이틀 도움말에서 일반 사냥 첫 안내가 먼저 보이고 검증 안내가 접혀 있는지 확인했습니다.
2. 검증용 사냥 시드90·빠른 지급·검증용 무기로 북쪽 탐험 → 마당 등불0° 배치 → 이동 종료 → 무리 출현을 진행했습니다. 근력+1/슬롯1로 공격 확정 전·비교 화면 경고를 확인하고 처리하여 토큰0, 적4/4, HP4, 처치0·유지0을 확인했습니다.
3. 이전 실제 QA 플레이의 첫 비교 저장(시드1061844653,10명령)을 UI 파일 선택으로 불러와 회피 없이 진행했습니다. 기본 피해2 후 HP4, 전용 능력 피해3 후 HP1, 다음 기본 피해2로 사망 요약을 확인했습니다. 확인 → 손패 보충 → 꿈 귀환 선택이 이어졌습니다. 사망 원인은 마지막 피해2이며 과거 라운드 피해를 합산하지 않습니다.
4. 타이틀의 새 QA 사냥에서 직접 지급으로 혈석1장을 선택하고 슬롯1에 장착했습니다. 손패로 변형 → 자동 재배치 창 → 슬롯3으로 옮기기 → 닫기 → 북쪽 탐험을 진행했습니다. 다음 슬롯3 공격은 **6+근력1+혈석1=8**입니다. 처리 후 부착·준비 상태와 슬롯3이 유지됩니다.
5. 그10명령 결과를 내보내고 UI로 불러온 뒤 다시 내보냈습니다. **12,567바이트, SHA-256 `ad5ba6ef12c540f2cee3e60216f00d3e081f7ea19fd4c0f1bc95a5f63a6ab7e3` 동일**입니다. 같은 실제 내보내기의 공개 명령 접두부를 엔진으로 재생해 공격 직전 지점을 만들었고, 그 파일을 UI로 불러와 최종 코드의 공격 전 예고·비교 표시도 재확인했습니다. 스냅샷·덱·체력·토큰을 손으로 편집하지 않았습니다.
6. 기본1280×720, 짧은1063×650, 좁은446×650에서 배치·핵심 버튼·손패 높이를 확인했습니다. 최종1063×650에서 설명143px, 손패175px/내용175px, 버튼과 화기가 화면 안에 있습니다. 실제 키보드 스크롤 후에도 버튼 위치는 유지됐습니다.446px에서는 페이지가 세로로 흐르며 가로 넘침이 없습니다. 임시 화면 크기 지정은 해제했습니다.

중간 배치에서1280×720의 설명 영역이0px로 줄어드는 문제를 발견하여 다시 조정했습니다. 최종 화면은 아래 별도 파일로 구분하며, 실패한 중간 배치의 스크린샷을 최종 증거로 사용하지 않습니다. 긴 무기 슬롯 텍스트는 기존 슬롯 영역의 세로 스크롤로 읽을 수 있고, 혈석 부착 배지는 맨 위에서 바로 보입니다.

## 자동 검증 범위

토큰 실제 명령·공개 정보 제한·독립 방해와 UI 공격까지, 사망 원인/예방/저널 롤링/모달 우선순위·무비용 확인, 타일 열람·이동, 도움말, 혈석의 유료·무료·반복 변형과 다음 공격·저장 왕복을 검사합니다. `tests/campaign-ui.test.cjs`의 오래된 도움말 문구 기대값은 dev.12의 회피 실행 안내를 의미 단위로 검사하도록 보완했습니다.

전체CI 기준선은 **2,789/2,789 통과**, 실패·취소·skip·todo0, 종료0,556.105초입니다. [결과](full-ci-result.json), [전](full-ci-before-hashes.json)·[후](full-ci-after-hashes.json)569개 코드·자산·검사 경로와 SHA가 같습니다. 기존 CI 정책의 원본 참고 사진 의존4항목 제외를 유지하며 원본 사진을 복사·업로드하지 않았습니다.

독립 검토에서 기준선 검사 뒤 새 UI의 경계 사례를 추가로 발견했습니다. **돌망치 소검3슬롯에 파편1번·덩어리3번 → 돌망치2슬롯으로 변형**하면 덩어리의 필수 재장착이 생기는데, 유효한 파편의 선택 재배치 창이 먼저 빈 내용으로 열렸습니다. 메인 재배치 버튼의 실제 활성 여부를 자동 열기의 조건으로 사용하여, 필수 재장착 뒤 선택 재배치를 열도록 보완했습니다. 덩어리 배지에도 피해+1뿐 아니라 속도+1을 함께 표시합니다.

이 마지막 두 표시 수정 후에는 [관련9파일170/170 검사](final-focused-result.json)를 다시 실행했고, [전](final-focused-before-hashes.json)·[후](final-focused-after-hashes.json)569경로 SHA가 동일합니다. 신규 돌망치 UI 회귀를 포함하며, 실제 브라우저에서도 소검→돌망치→소검→돌망치로 반복 변형하여 빈 팝업 없이 필수 배치가 먼저 진행되고 그 뒤 두 부착물을 재배치할 수 있음을 확인했습니다. **전체CI2,789개는 이 마지막 보완 전 기준선이고, 최종 코드에 전체CI를 재실행했다고 주장하지 않습니다.** 두 검사 수를 합산하지 않습니다.

과거 dev.11 전체CI나 dev.12의50개 결과도 이번 결과에 합산하지 않습니다. 이번 실제 브라우저 작업은 위 시나리오이며, 챕터1~3·모든 무기의 전 흐름을 다시 수동 완주했다는 의미가 아닙니다.
