# 장치무기 후속 피해 대상 연출 — BB-026 실제 재현과 재검증

슬롯을 비울 때 적에게 피해를 주는 장치무기 세 종류에서, **같은 이름의 적 #2를 선택했는데 피해를 받지 않은 #1에도 먼저 타격 연출이 나오던 문제**를 실제 Chromium에서 재현하고 수정 후 다시 확인했다. 엔진은 처음부터 #2에게만 피해1을 적용했다. 잘못된 두 번째 피해나 적의 실제 이동이 아니라, 공개 결과를 타격 모션으로 옮기는 adapter의 대상 선택 오류다.

이 문서는 이 오류의 **세 사례만** 다룬다. 전체 30개 무기 형태의 후속 선택·다음 이동·다음 전투, 추가 무기 분기 통합 검사와 최종 전체 CI는 별도 작업이다. 이전 [지도 모션 배치 기록](../map-motion-ui-qa-v0.8.13-dev.6/README.md)의 완료 범위와 미확인 항목은 그대로 보존한다. [Issue #33](https://github.com/dfrpg98-jpg/bloodborne-solo/issues/33), [PR #15](https://github.com/dfrpg98-jpg/bloodborne-solo/pull/15)에서 관리하며 병합·정식 릴리스 완료를 뜻하지 않는다.

## 재현 예시와 수정

검증용 플레이모드에서 일반 장치무기를 선택하고 seed140의 정상 명령으로 민가의 위쪽 거리 칸(`tile-11:street`)에 재앙의 야수 #1·#2와 야수 사냥 하인 #1을 모았다. 하인을 `card-6/slot0`으로 공격해 슬롯을 채운 다음, 검증용 손패 보충으로 그 슬롯을 비웠다. 슬롯 비우기 피해의 대상 선택이 뜨면 **재앙의 야수 #2**를 선택했다. 각 결과 JSON의 `preparationCommands` 15개와 `trigger`를 그대로 재생할 수 있다.

검증용 시작 지급은 회복약10개·손패 보충10개·이동10개이며, 이 준비에서 실제 소모한 검증 자원은 이동 `item-qa-1-21/22`와 손패 보충 `item-qa-1-11/12` 각2개다. 상태를 손으로 조립하거나 사용자 자동 저장을 편집하지 않았다. 준비 상태는 엔진의 정상 명령으로 만들고 제품의 파일 불러오기 UI로 가져왔으며, 실제 피해 대상 선택은 Chromium에서 제품 버튼을 클릭해 수행했다. 캠페인을 처음부터 연속 완주한 증거로 취급하지 않는다.

수정 전에는 adapter가 공개 로그의 `재앙의 야수`라는 이름만 보고 먼저 발견한 #1을 골랐다. 실제로 #1의 체력은4로 유지되고 #2만4→3이었으므로, #1에 피해0의 잘못된 타격을 만든 뒤 공개 체력 변화에서 #2의 진짜 타격을 추가해 연출이 두 번 나왔다. 수정 후에는 **명령에 명시된 대상 → 실제 공개 체력 감소 → 전투 대상 → 후보가 하나뿐인 경우** 순으로 대상을 결정한다. 이름이 같고 모두 체력이 그대로이며 다른 확정 근거가 없는 경우에는 임의의 타격을 만들지 않는다. 실제 범위 피해·방어로 피해0이 된 확정 대상·처치된 대상의 연출은 별도 회귀 검사로 유지한다. 엔진 피해·무기 규칙·저장 명령은 변경하지 않았다.

## 원본 화면 증거

아래 여섯 PNG는 각 실행의 `first-impact` 표본 원본이다. 수정 전에는 #1 쪽에 먼저 타격 표시가 있고 수정 후에는 선택한 #2 쪽에 표시가 보인다. 파일 이름이 모든 첫 프레임을 계측했다는 뜻은 아니다. 실제 요청·촬영 시점은 각 결과 JSON의 `requestedAtMs/capturedAtMs`에 기록하며, 사진만으로 중간 모션 전체의 자연스러움이나 연출 정확한 밀리초를 보장하지 않는다.
