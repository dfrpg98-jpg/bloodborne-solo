# 0.8.13-dev.1 출시 전 엄격 점검

2026-10-13의 개발 점검입니다. 사용자는 정식 릴리스 전에 규칙과 오류 가능성을 검토하고 Unity 개발을 준비하도록 요청했습니다. 정식 릴리스·태그·main 병합은 이 작업의 완료 조건이 아닙니다.

## 판정과 확인된 오류

현재 확인한 기존 실행 오류2건과 새 구현의 안내/이식 계약 문제5개 항목을 수정했습니다. [BB-001~007 목록](../bugs.md)에 재현 예시, 수정 전·후, 출처와 회귀를 남겼고 각 GitHub Issue에서 검토합니다. 준비물의 문제를 기존 출시본의 런타임 오류로 확대하지 않습니다. 검사를 통과해도 모든 버그가 없거나 출시할 준비가 끝났다고 판정하지 않습니다.

## 원문과 대조한 범위

- 제공된 한국어 규칙서12/14/15/16/19~21/24/26쪽을 직접 렌더링해 읽었습니다. 이름 붙은 칸, 탐험 진입·이동 비용, 다중 상호작용, 공격 속도·동시 피해·즉시 사망, 안개/망가진 등불, 순간이동의 이동 판정을 대조했습니다.
- 원본 임무60개·챕터6개·타일20개의 사진을 직접 확인했습니다. 임무60개의 SHA-256은 앞선 원문 점검과 일치합니다.
- [CMON 공식 FAQ v1.0](https://www.cmon.com/wp-content/uploads/2023/06/Bloodborne_Boardgame_FAQ_v1.0.pdf)6쪽을 읽고 즉시 카드 효과, 이동한 공격의 후속 효과, 사망 후 치유 불가, 보스 페이즈 전환 중 기존 공격, 임무의 추가 적/계몽 토큰 및 임무20 정정을 대조했습니다.
- 현재 모듈의 전투·화기·무기·보상 순서, 일반 적/보스 페이즈, 카드 비용·슬롯, 이동/출입구/탐험, 동행 생존자와 유료 상호작용, 임무 위치·완료·분기, 장비 선택·꿈·챕터 전환, 명령 저장과 UI 공개 범위를 검사합니다.

## 실제 완료한 검증

최종 로컬 전체 결과는 `release-readiness-results.json`에 기록합니다. 원격 CI는 해당 PR/Actions 실행과 아티팩트의 실제 완료 결과를 별도로 확인합니다. 아래 개별 결과를 전체 검사 합계에 중복하여 더하지 않습니다.

- 원본 사진 대조를 포함한 게임 전체 회귀2548개 통과/0실패/0취소/0건너뜀,417.224초. 테스트 파일88개이며4개 원본 사진 검사도 실행했습니다.

- 전투 수정12개, 컨트롤4개, 자연 납골당 검사2개. 자연 전투99/50명령과 구체적인 동시 사망/복수 문자/연쇄 무기 조립 경계를 구분했습니다.
- 독립 전투 이어가기 검토46분기. 필수 장비 선택, 연쇄 무기·임무 사망/완료, 적 진입 처치, 자연 진행의 실제 컨트롤 및 저장 재생을 점검했습니다.
- 과거 임무/동행/QA 이력 통합101개, 예배당15개, 화면/지도/연출 통합151개 통과. 고정된 과거 입력은 명시적 규칙13으로 보존하고 별도로 현재 규칙14를 검사합니다. 현재 처리를 통과시키려고 과거 기대 결과를 바꾸지 않습니다.
- 실제 브라우저: localhost8792의 별도 저장소에서 유효한 자연 전투 저장을 불러와 체력4→5→1 생존 및 기절 버리기 후 플레이어 차례를 확인했습니다. 사용자 주소8784의 저장에 QA 진행을 쓰지 않습니다.
- 이후 브라우저 접근 거부가 전달되어 새로고침 복원·추가 납골당 브라우저 확인은 중단했습니다. 이 두 동작을 실제 브라우저에서 검증했다고 기록하지 않습니다. 저장 복원과 납골당 후보는 자연 엔진·실제 컨트롤 회귀로 검사했습니다.
- Unity 준비: 최종 생성본의 결과는 `unity-port/Validation/*.json`에 보관합니다. 생성기는 현재 출처·버전·dirty 상태·파일 해시를 기록하며 이전 커밋을 수정되지 않은 코드인 것처럼 소개하지 않습니다.
- 실행 ZIP의 파일515개를 실제 바이트/해시로 검사했습니다. 원본 참고 사진, Unity 중복 생성 묶음, 관리 문서는 게임 실행 ZIP에서 제외합니다. 점검용 ZIP이며 정식 릴리스·태그가 아닙니다.

## 저장과 공개 정보

새 규칙14는 처치 시 선택창과 이어가기 상태를 저장합니다. 규칙11~13은 저장 당시 명령으로 먼저 검증하고, 그 뒤 기록된 현재 처치 판정 채택을 적용합니다. 예배당 순서 채택도 같은 기존 원칙을 따릅니다. 변조되거나 지원되지 않는 저장은 거부하고 현재 브라우저 저장을 보존합니다.

Unity 프런트엔드에는 명시적으로 허용한 공개 snapshot/행동만 전달합니다. 난수, 덱 순서, 미공개 임무 결과, 내부 이어가기 상태는 oracle의 private 상태에 둡니다. 저장 내보내기는 별도 명시적 연산이며 화면 binding으로 사용하지 않습니다. 공개 allowlist와 poison 검사는 보안적으로 암호화된 출시 구조를 구현했다는 뜻이 아닙니다.

독립 준비물 검토에서 발견한 장면 ID의 시드 노출은 BB-004로 수정했습니다. 세션 ID를 내부 시드와 분리했고 실패한 새 시작/불러오기가 기존 진행을 덮어쓰지 않는 검사도 추가했습니다.

JSON Schema 등록 참조/합법 null, C# ISO 문자열 보존, 토니트루스 연습의 공개 외형 재생도 각각 BB-005~007로 수정했습니다. 실제 Ajv 구조 검사와 실제 C# DTO compile/runtime 검사를 추가했으며 Unity Editor나 전체 C# 규칙 엔진이 실행됐다는 뜻은 아닙니다.

## 남은 불확실성과 출시 보류 범위

- 임무18/21/41의 단위가 한국어 원문에 명시되지 않았습니다. 공식 FAQ의 확정 답을 확보하지 못했으므로 타일 전체 해석은 사용자 재정으로 유지합니다. 예배당37→39→56의 호위 우선도 사용자 재정입니다.
- 안개를 사이에 둔 모든 무기/원거리 피해의 범위와 자비의 칼날 연속 공격의 점유 슬롯 보너스 계산 시점에는 확정 원문 해석을 확보하지 못했습니다. 재현된 구현 오류와 섞지 않았고 임의로 규칙을 바꾸지 않았습니다.
- 생존자 도망·기증의 추가 조사에서는 확정 오류를 확인하지 못했습니다. 두 자연 진행의12상태 탐색만으로 모든 도망 경로가 검증됐다고 하지 않습니다.
- 다른 캠페인·멀티플레이·장시간 다양한 직접 플레이, 전체 Unity C# reducer, 실제 Editor/장면·입력·지도·스프라이트/애니메이션 검증은 완료되지 않았습니다. 기존 외형 재작업과 UI/UX Issue도 계속 남아 있습니다.
- 검증용 무기로 얻은 승리는 정규 무기 캠페인 완주와 구분합니다. 이미지 렌더링, DOM harness, 자연 엔진 재생, 실제 브라우저, 사용자 플레이는 서로 다른 증거입니다.

## Unity로 이어갈 때

[Unity 준비 안내](../../unity-port/README.md)와 [후속 이식 Issue#8](https://github.com/dfrpg98-jpg/bloodborne-solo/issues/8)에 데이터·명령·저장·공개 정보·에셋·좌표 계약을 기록합니다. JS 함수를 JSON만으로 옮길 수 없으므로 원본 모듈과 명령별 결과 기준을 함께 보존했습니다. 이미 설치된 Node와 C# compiler로 준비물 검증을 수행하며 Unity 설치는 이 준비에 필요하지 않습니다. 실제 Editor 개발 시에는 [공식 지원표](https://unity.com/releases/unity-6/support)의 Unity6.3 LTS를 기준 후보로 삼되 설치할 정확한 patch와 Editor compile 결과를 기록해야 합니다.
