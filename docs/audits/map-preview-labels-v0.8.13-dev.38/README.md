# 지도 미리보기와 칸 이름 검증 — 0.8.13-dev.38

칸 이름을 타일 밖의 공통 행에서 제거하고, 회전된 각 칸의 아래쪽 안쪽 경계에 배치했다. 글자는 회전하지 않으며 화면상 방향을 표시한다. 지도 100%의 기존 배율 1.44는 유지한다. 작은 타일에서도 28px 출입구 버튼이 이름을 덮지 않도록 남쪽의 세로 여유와 동·서쪽의 가로 여유를 확보했다.

이번 제품 변경은 `src/hunt-app.js`의 지도 이름 렌더링, `src/tile-geometry.js`의 표시 위치 계산, `styles/hunt-map-interaction.css`의 이름 배치에 한정된다. 타일 SVG나 이미지 경로를 수정하거나 실패한 이미지를 대체 그림으로 가리는 코드는 추가하지 않았다.

## 확인된 결과

- Chrome 155의 임시 프로필에서 20종 지도 SVG가 모두 HTTP 200, `image/svg+xml`, `Image.decode()` 1000×1000으로 확인됐다. `file://`로 직접 실행했을 때도 20종 모두 같은 크기로 해독됐다.
- 실제 게임에서 정상 캠페인의 공개 명령으로 도달한 성배 교단 예배당·오에돈 예배당·민가 미리보기를 공식 파일 가져오기로 열었다. 가능한 회전을 각각 선택하고 실제 배치 버튼을 눌렀다. 미리보기와 배치 후 그림이 정상이며, 칸 이름의 위치·방향·직립 표시가 일치했다. 내보낸 저장은 독립 실행한 `PLACE_TILE`과 해당 시점에 기록되는 기존 판정 채택 명령의 결과와 정확히 일치했다.
- 별도의 표시 컴포넌트에서는 제품 CSS와 동일한 지도 표시 계산으로 20종×4회전을 타일 크기 290px·170px에서 검사했다. 지도 배율은 1.44이며, 총 160개 조합·416개 이름의 네 모서리가 자기 칸 안에 있고 글자가 직립하며 출입구 버튼과 겹치지 않았다. 이 전수 검사는 새 게임 상태를 주입한 캠페인 플레이 검증이 아니다.
- 실제 게임 검사 3건은 정상 캠페인 공개 명령의 저장 재생 증거다. `tests/fixtures/map-preview-dev38-recipes.json`에는 재현용 설정과 명령만 보관한다. 생성한 저장·게임 화면 캡처·다운로드 결과는 추적하지 않는 `test-results/map-preview-dev38/browser/`에 둔다. 사용자 저장과 사용자 브라우저 프로필은 사용하지 않았다.

## 깨진 이미지 신고와 서버 점검의 구분

작업 초기 점검에서는 `http://127.0.0.1:8860` 연결 거부를 확인했다. 별도 백그라운드 서버 복구 후 이 검사 전체와 마지막 이미지 요청이 성공했다. 미리보기와 배치된 타일은 동일한 `assets/tiles/map/tile-XX.svg` 경로를 사용하며, 20종 모두 Git에 포함돼 있고 로컬 XML 파싱도 정상이다.

사용자가 처음 보았던 깨진 이미지의 당시 요청 로그를 확보하지 않았으므로 원인을 서버 중단으로 확정하지 않는다. 이 검사에서 자산 손상이나 잘못된 미리보기 경로는 재현되지 않았고, 점검 중 확인한 서버 중단을 복구한 뒤 정상 표시를 확인했다.

## 재실행

저장소 루트에서 서버가 이미 실행 중인 상태로 아래를 실행한다. 검사 도구가 서버를 직접 시작하거나 종료하지 않는다.

```powershell
node docs/audits/map-preview-labels-v0.8.13-dev.38/verify-browser.cjs
node --test tests/map-preview-labels-dev38.test.cjs tests/map-interaction-dev36.test.cjs
```

기본 서버 주소는 `http://127.0.0.1:8860`이다. 다른 주소는 `BB_PREVIEW_ORIGIN`, Playwright 모듈 경로는 `BB_PLAYWRIGHT_MODULE`로 지정할 수 있다. 기본값은 Codex에 번들된 Playwright이며 설치된 Chrome을 샌드박스로 실행한다. 최종 `verification.json`에 제품 파일의 검사 전·후 SHA-256, 브라우저 버전, 이미지 및 라벨 검증 결과를 기록한다.
