## BB-001 · 빠른 범위 처치 효과보다 느린 공격이 먼저 진행됨

- 발견 범위: 0.8.12의 규칙11~13 처리. 원문 근거가 있는 구현 오류입니다.
- 예시: 플레이어 체력4, 장송의 칼날 칼날 형태. 속도3 공격의 범위 피해로 주변 적A를 처치합니다. 주 대상 재앙의 야수B는 체력3으로 살아 있고 속도1·피해4·기절 공격이 남아 있습니다. 플레이어는 ‘적을 처치할 때’ 사용하는 피의 기쁨과 야수 문자를 장착했습니다.
- 수정 전: 한 번의 전투 해결 명령이 느린 B의 공격까지 진행합니다. 피의 기쁨의 손패 뽑기·치유를 선택하기 전에 플레이어가 사망해 꿈으로 이동합니다. **처치된 A가 다시 공격한 사례가 아닙니다.**
- 수정 후: 속도3의 동시 피해 묶음을 모두 처리하고 살아 있는 플레이어에게 처치 효과 선택을 표시합니다. 피의 기쁨으로 체력5 → 전투 계속 → B의 피해4 → 체력1 → 기절 손패 버리기 → 플레이어 차례로 복귀합니다. 트랙과 라운드는 해당 전투에서 바뀌지 않습니다. 야수 문자로 남은 적을 처치하는 선택도 가능합니다.
- 경계: 같은 속도의 피해는 먼저 모두 처리합니다. 같은 속도로 사망한 플레이어는 처치 치유로 부활하지 않습니다. 필수 장비 선택과 연쇄 무기 효과를 마친 뒤 전투를 한 번만 이어갑니다. 소진한 문자는 다시 사용할 수 없습니다.
- 근거: 제공된 야수/황홀 문자 원문을 보존한 `components/cards.json`의 timing·효과, 한국어 규칙서19~21쪽. [공식 FAQ2쪽](https://www.cmon.com/wp-content/uploads/2023/06/Bloodborne_Boardgame_FAQ_v1.0.pdf)의 사망 후 공격 치유 불가와 대조했습니다. 예배당이나 임무 위치의 사용자 재정과 구분합니다.
- 자연 재현: seed140, `tests/fixtures/natural-fast-kill-reaction-v14.json`의99공개 명령. 전투 연습의 보상 지급을 사용하며 상태 수동 편집은 없습니다. 정규 캠페인 완주 증거와 구분합니다. seed1의50명령 재현도 보존합니다.
- 회귀 검사: `combat-kill-reaction-v14.test.cjs`의12개 자연/조립 경계 검사, `kill-reaction-ui-v0813.test.cjs`의 실제 컨트롤·저장 채택 검사. 독립 검토46분기에서도 이어가기 중복과 선택 접근을 확인했습니다.
- 브라우저: 격리된 localhost8792에서 원래 엔진이 만든 유효 저장을 불러온 뒤 피의 기쁨 → 반응 종료 → 기절 버리기를 실제 버튼으로 수행해 체력4→5→1과 플레이어 차례 복귀를 확인했습니다. 사용자의 실제 플레이 기록과 구분합니다.
- 호환: 규칙14가 새 시작 기준입니다. 규칙11~13의 저장은 원래 명령/결과를 정확히 검증한 뒤 현재 판정 채택 명령을 별도로 기록합니다. 과거 저장을 조용히 새 결과로 덮어쓰지 않습니다.

## BB-002 · 봉쇄된 납골당이 순간이동 후보에 표시됨

- 발견 범위: 0.8.12의 후보 조회. 실제 이동 검증은 이미 거부하고 있었습니다.
- 예시: 챕터3, 임무41 공개, 현재 챕터 계몽2개 미충족. 중앙 등불에서 상호작용을 준비하면 봉쇄된 납골당 위 칸과 아래 등불 칸이 순간이동 목적지로 표시됩니다.
- 수정 전: 수행 가능한 것처럼 선택할 수 있으나 `INTERACT`에서 진입 거부 오류가 발생합니다. 이 문제를 실제 봉쇄 우회라고 기록하지 않습니다.
- 수정 후: 후보 조회에도 기존 `missions.canEnter`를 사용하여 두 칸을 제외합니다. 봉쇄 해제 뒤 합법적인 진입과 다른 정상 등불·허용된 안개 목적지는 유지합니다.
- 자연 재현: seed90, 장송의 칼날 낫 형태, 규칙13. `full-campaign-actual-v10-commands.json`의 앞278명령. 원래 저장을 정확히 검증한 상태입니다.
- 근거: 임무41 원문, 한국어 규칙서24/26쪽. 41의 타일 전체 봉쇄 범위는 [사용자 채택 재정](decisions.md)이며 공식 FAQ에서 범위를 확정했다고 하지 않습니다.
- 회귀 검사: `mission-rc-audit-v0812.test.cjs`의2개 검사와 안개·망가진 등불5개 검사. 납골당 후보 제외, 명령 실패의 원자성, 저장 재생을 검사합니다. 기존 `later-missions.test.cjs`의 해제 전/후 진입도 유지합니다.

## BB-003 · 처치 문자 기회 종료 안내가 새 반응창과 불일치

- 발견 범위: 이번 처치 반응창 구현의 독립 검토. 과거 출시본의 독립 오류라고 확대하지 않습니다.
- 예시: 처치 후 야수 문자로 다른 적에게 피해2를 주면 피의 기쁨도 계속 사용 가능합니다. 그런데 장비·보상에는 다른 행동을 하면 기회가 끝난다고 표시했습니다.
- 수정 전: 합법적인 두 번째 문자 선택을 포기하게 만들 수 있는 안내입니다.
- 수정 후: 다른 처치 문자도 사용할 수 있으며 ‘처치 효과 사용 마치기’를 누르면 기회가 끝난다고 안내합니다. 기존 규칙의 재생 상황에는 기존 종료 안내를 유지합니다.
- 회귀 검사: `kill-reaction-ui-v0813.test.cjs`의 자연50명령 상태에서 야수→피의 기쁨을 실제 컨트롤로 실행하고 저장·문구를 대조합니다. 소진한 문자 재사용은 엔진에서 거부합니다.

## BB-004 · Unity 공개 장면 ID에 내부 시드가 포함됨

- 발견 범위: 이번 Unity 준비물. 기존 웹 출시본의 새 오류라고 확대하지 않습니다.
- 예시: 시드90으로 시작한 oracle의 공개 `sceneId`가 `90:1:unity-prep`였습니다. 필드명이 initialSeed가 아니어도 내부 난수 입력이 공개 ID에 포함되어 있습니다.
- 수정 전: 공개 정보를 소비하는 UI에서 준비 시드를 읽고 결정적인 덱 준비 입력을 재구성할 수 있습니다. 공개 계약이 내부 시드를 숨긴다는 설명과 불일치합니다.
- 수정 후: 시드에서 유도하지 않은 세션 식별자와 공개 챕터만 사용합니다. 명령 수행 중에는 같은 ID를 유지하고 성공한 새 시작/불러오기에서만 바꿉니다. 실패한 불러오기는 진행과 ID를 보존합니다.
- 근거: 플레이어에게 아직 공개되지 않은 정보를 보여주지 않는 요구와 Unity public projection 계약. 보드게임의 특정 행동 규칙 정정과 구분합니다.
- 회귀 검사: `unity-port/tests/preparation.test.cjs`의 seed poison 및 세션 생명주기 검사. 명령별 golden은 변경된 공개 계약으로 재생성하며 엔진의 비공개 상태·판정은 바꾸지 않습니다.

## BB-005 · 저장 schema 참조와 합법적인 null 명령 불일치

- 발견 범위: 이번 JSON 계약의 실제 Ajv8.20 검사. 두 구체적인 불일치를 함께 보존합니다.
- 예시A: 저장 schema의 `$id`가 URN인데 상대 경로로 명령 schema를 참조해 컴파일이 `URN without nid cannot be serialized`로 실패합니다. 수정 후 등록된 명령의 절대 URN을 참조합니다.
- 예시B: 원본이 `{type:'END_TURN',hunterId:null}`을 받아 저장·재생하지만 schema가 string만 허용해 거부합니다. 수정 후 string/null을 허용하고 중첩 선택의 누락·null·boolean을 보존합니다.
- 근거: 원본 명령/저장 보존 계약 및 [JSON Schema 공식 참조 규칙](https://json-schema.org/understanding-json-schema/structuring). 구조 검사와 실제 행동 검증은 다릅니다.
- 회귀 검사: `unity-port/tools/verify-schemas.cjs`가 이전 참조 실패를 재현하고76저장·14,477명령·1,300공개 checkpoint 및 음성 사례를 실제 validator로 검사합니다.

## BB-006 · C# 저장 후보에서 날짜 문자열을 변환함

- 발견 범위: 이번 C# DTO 읽기 코드. `recordedAt`는 필수 게임 데이터라는 뜻이 아니라 원본이 보존하는 임의 명령 payload의 재현 예시입니다.
- 예시: 원본 문자열 `2026-10-13T12:00:00.000+05:30`이 기본 JObject.Parse에서 Date 토큰이 되어 이 PC에서 `2026-10-13T15:30:00+09:00`으로 직렬화됩니다. 원본 JS는 같은 문자열을 정확히 저장·재생합니다.
- 수정 후: `DateParseHandling.None`으로 읽어 원래 값/offset을 보존합니다. 중복 키와 뒤에 붙은 JSON도 거부합니다.
- 회귀 검사: 실제 `PortContracts.cs`를 PowerShell Roslyn/Newtonsoft로 컴파일한21개 런타임 검사. `tools/verify-csharp-contracts.cjs`와 `.ps1`에 원본 save/content·공개 경계 검사를 함께 보존합니다. 실제 Unity Editor/package compile과 구분합니다.

## BB-007 · Unity oracle에서 토니트루스 연습 공격이 실패함

- 발견 범위: 이번 공개 외형 adapter. 기존 웹 출시본의 동일 오류라고 단정하지 않습니다.
- 예시: seed90, 토니트루스, 전투 연습의 교단의 하인을 상대로 손패card-3/slot0 공격. 원본은 `combat_react`, revision1로 진행하지만 oracle은 충전 외형 복원용 원래 설정 재생에 `campaign:false`를 명시하지 않아 오류를 내고 revision0에 남습니다.
- 수정 후: 외형 복원 재생에서 campaign을 명시적 boolean으로 전달합니다. 원본 공격 비용·판정과 충전 여부는 보존합니다.
- 회귀 검사: `unity-port/tests/preparation.test.cjs`에서 충전/미충전 실제 명령, 원본 결과와 같은 저장, 새 불러오기의 공격 외형을 확인합니다.

## BB-008 · 이오세프카 공격 선택 후 현재 목표가 갱신되지 않음

- 발견 범위: 0.8.13-dev.1의 공개 목표 문구. 임무 판정 자체의 오류는 아닙니다.
- 예시: 챕터3의 진실 임무에서 이오세프카를 공격하기로 선택합니다. 선택이 해결되고 이오세프카 전투가 시작된 상태에서도 현재 목표는 ‘이오세프카를 공격하거나 실험을 돕기’를 표시했습니다.

## BB-009 · 임무 지시문의 조사와 명령문 종결 누락

- 발견 버전·범위: 0.8.13-dev.2의 현재 목표와 임무 알림, P3 · 안내. 실제 검증용 플레이모드의 챕터2·3에서 확인했습니다.
- 예시: 챕터3 대교의 ‘무리를 정리하다’ 임무가 출현하면 ‘재앙의 야수를 처치해 계몽 토큰 제거.’를 표시했습니다. 수정 후에는 ‘재앙의 야수를 처치해 계몽 토큰을 제거하세요.’를 표시합니다.
- 다른 예시: ‘성직자 야수 봉인해 두세요.’ → ‘성직자 야수를 봉인해 두세요.’, ‘진료소에서 재앙의 야수 처치하세요.’ → ‘진료소에서 재앙의 야수를 처치하세요.’, ‘소모품 기부하세요.’ → ‘소모품을 기부하세요.’

- 회귀 검사: 공개 문구·목표 노출·임무 알림 관련107개 통과. 같은 유효 QA 저장을 제품 UI로 불러와 연구·대교·봉인·무리 정리·기부·진료소51의 수정 문구와 확인 비용을 실제 브라우저에서 재검증했습니다. [브라우저 증거](audits/mission-browser-qa-v0.8.13-dev.3/results.json)에 원래 문구와 수정 후 화면을 보존합니다.
- 관리: [Issue #16](https://github.com/dfrpg98-jpg/bloodborne-solo/issues/16), [PR #15](https://github.com/dfrpg98-jpg/bloodborne-solo/pull/15). 개발본0.8.13-dev.3이며 병합·정식 릴리스에서 해결됐다는 뜻은 아닙니다.

## BB-010 · 같은 칸의 적 이미지가 보스 마커 클릭을 가로챔

- 발견 버전·범위: 0.8.13-dev.2 지도 대상 선택, P2. 실제 브라우저에서 두 번 같은 결과를 재현했습니다.
- 재현 예시: 검증용 QA 저장 `chapter3/main/before-final-win.json`을 제품의 ‘불러오기’로 연 뒤, 오에돈의 지하묘지 아래 칸에 있는 성직자 야수의 마커 중앙을 누릅니다. 같은 칸의 아래쪽 재앙의 야수 #2가 선택되어 그 적에 대한 공격 버튼이 표시됩니다. 키보드 Enter로 보스를 선택하면 정상 공격할 수 있었습니다.
- 원인: 실제32×32 마커는 약40px 간격으로 겹치지 않았지만 아래 적의66×88 투명 `::before` 영역이 위로58px 확장되어 보스 마커 중앙을 덮었습니다. 실제 `elementFromPoint` 결과도 `scourge-beast-2`였습니다.
- 수정 후: 장식 이미지 영역에 `pointer-events: none`을 적용했습니다. 같은 저장에서 각 마커 중앙의 hit-test와 실제 클릭을 보스 → 재앙의 야수 #1 → #2 → 보스 순서로 확인했으며 모두 의도한 적이 선택됐습니다. 마우스로 보스를 선택해 최종 처치 알림도 확인했습니다.
- 범위·검사: 실제32×32 마커의 선택은 유지하고 투명 확장 영역의 클릭은 제거합니다. 적의 좌표·배치와 엔진·저장 형식은 바꾸지 않습니다. 기존 지도·선택·표현60개 검사 통과와 실제 브라우저 포인터 회귀를 구분해 기록합니다.
