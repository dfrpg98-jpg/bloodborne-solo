기준: 2026-10-12 / 기나긴 사냥 챕터 1~3 솔로

현재 목표
지도 위 상황을 읽고 가능한 행동을 선택하면 게임이 비용·전투·임무 진행을 처리하는 흐름을 만듭니다. 기존 칸 이동·기술 지불·슬롯·정보 공개 규칙을 유지하며 반복적인 창 이동과 내부 데이터 용어를 줄입니다.

이번 표시 개선
1. 상태·사냥 트랙·현재 주 목표를 고정하고 손패·무기·화기를 하단에 모았습니다. 무기 고유 효과와 화기의 사용 효과·준비 조건을 항상 읽습니다.
2. 칸·출입구·적을 직접 선택하면 행동과 비용·불가 이유가 나타납니다. 실행 전에 대상·기술·슬롯을 바꾸되 미공개 정보를 열지 않습니다.
3. 현재 챕터에 공개된 장소의 계몽 단서 조건을 목표 영역에서 확인합니다. 실제 공개된 임무를 우선 보여주며 다음 챕터나 미래 보상은 예고하지 않습니다.
4. 내부 번호 공개·면 구분 대신 이야기·임무·기술·장비·소모품·현재 무기 형태를 사용합니다. 조건 지시는 완결된 문장으로 정리합니다.
5. 자동 판정한 예배당 사건은 실제 처리한 분기만 보여줍니다. 나중에 다른 조건을 충족해도 과거 사건의 결과를 덮어쓰지 않습니다.
6. 목표의 색 표식이나 적 이름에서 도감을 엽니다. 적 행동 기록은 현재 공용 덱의 공개·버림 순서를 보여주며 실제로 다시 섞을 때 초기화합니다.
이 표현 변경은 규칙 원문·저장 값·임무 번호·기존 명령 재생을 바꾸지 않습니다.

시각 자료의 현재 상태
장치무기 15종의 30개 형태에 원본 정지 외형을 등록했습니다.
적 6종을 11개 행동 구성·보스 페이즈에 연결합니다. 현행 방식은 확보된 원작 그림·게임 프레임의 픽셀을 사용하고 배경을 투명하게 분리하는 것입니다.
무기의 원작 연속 동작은 0개입니다. 야수 사냥 무리의 접근·회수 조각 4개 원본 프레임(39~42, 약 320ms)을 두 행동 구성의 이동에 연결했습니다. 완전한 걷기 주기나 고유 공격을 확보한 것은 아닙니다. 85개 무기 슬롯과 36개 적 행동의 효과 연결을 원작 고유 모션의 확보로 계산하지 않습니다.
성직자 야수는 1페이즈 정면과 2페이즈용 측면을 같은 원본 모델 그림에서 사용합니다. 다른 관찰 각도이며 원작의 2페이즈 전용 신체 변화나 고유 모션을 확보한 것은 아닙니다. 현재 무리 외형은 횃불·도끼 변종입니다. 방패·장총·병 변종의 외형과 고유 동작은 아직 확보하지 않았습니다. 여성 환자는 더 선명한 1000×808 원작 게임 화면의 전신으로 바꿨습니다. 반대 팔과 다리 일부는 원본 망토에 가려져 있으며, 해당 부분을 복원하지 않습니다. 원본 경계의 잘린 끝부분도 자료 한계로 기록합니다.
여성 환자 Grab 영상의 몸을 낮추는 준비 동작은 개발 시제품입니다. 실제 붙잡기 접촉·구토 분사를 확인하지 못했고 윤곽 판정이 불확실해 게임 외형이나 고유 공격 은행으로 활성화하지 않았습니다.

다음 작업 순서
1. 원작 연속 모션 확보: 각 무기·적의 준비→공격→회수, 걷기·피격·사망과 실제 변형을 확보한 범위부터 연결합니다. 정지 그림을 반복하거나 방향 뷰를 섞어 원작 동작이 완성되었다고 표시하지 않습니다.
2. 원본 외형 부족 보완: 무리의 다른 복장·화기·방패·병 변종과 원본에 가려진 부분을 확인합니다. 모자나 복장이 다르다는 이유만으로 같은 종의 무리를 다른 적으로 배제하지 않습니다. 확보하지 못한 부분은 임의로 복원하지 않습니다.
3. 플레이 중 정보 밀도 점검: 목적지·비용·대상·현재 임무를 읽는 시간을 확인하고, 손패가 늘거나 꿈·필수 보상·강제 이동이 겹칠 때 주요 조작을 찾기 쉬운지 점검합니다.
4. 이야기와 결과 연출: 공개된 장면·보상·챕터 종료를 읽은 뒤 같은 지도와 선택 상태로 돌아오는 흐름, 음향과 짧은 결과 피드백을 개선합니다. 미래 이야기와 보상은 해당 시점 전까지 표시하지 않습니다.
5. 접근성: 동작 줄이기·키보드 초점·텍스트 크기·색 이외의 상태 구분을 점검합니다. 연출을 줄여도 규칙 선택과 공개 순서를 유지합니다.
현재 규칙 엔진을 유지하고 Phaser 표시 계층에 이어 붙입니다. 이번 작업 때문에 Unity 설치를 요구하지 않습니다. 다른 캠페인·멀티플레이는 사용자가 추가 요청한 단계에서 별도로 검토합니다.
차단된 원본 자료는 링크를 전달하고 사용자가 참고자료에 넣어 준 로컬 파일을 확인합니다. 막힌 다운로드의 우회나 반복은 하지 않습니다.
