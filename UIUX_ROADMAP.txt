블러드본 솔로 — UI/UX 레퍼런스 분석과 작업 순서

개선의 중심
현재 게임에 필요한 변화는 기능 목록을 더 늘리는 일이 아니라, 지도 위의 상황을 보고 행동을 고르면 게임이 계산과 진행을 맡는 경험이다. 무기 슬롯과 손패, 이동 비용, 적 활성화, 임무 공개 순서는 보드게임 규칙을 유지하되 플레이어가 창 사이를 오가며 계산하거나 처리 순서를 찾아야 하는 부담을 줄인다.

아래의 ‘확인한 사례’는 공식 사이트·개발자 설명·공식 배급 페이지에서 확인했다. ‘적용 제안’은 그 사례를 현재 게임에 맞춰 해석한 설계안이다. 이번 조사에서 다른 게임을 직접 구매하거나 실행하지 않았으며, 스크린샷만으로 키 입력 이후의 실제 동작까지 검증했다고 주장하지 않는다. 레퍼런스의 그림·아이콘·음악을 가져오는 계획도 아니다.

1. Darkest Dungeon — 화면의 주인공과 정보 위계
확인한 사례: Red Hook의 공식 Steam 전투 스크린샷은 큰 전투 장면을 중앙에 두고, 선택한 영웅의 상태와 기술을 하단에 모은다. 선택 영웅과 기술은 황색으로 강조되며 지도는 별도 작은 패널에 들어간다. 공식 설명에는 성공과 실패를 전달하는 내레이션 시스템도 명시되어 있다.
적용 제안: 지도/전장을 가장 크게 두고, 선택한 사냥꾼·적·출입구의 정보만 자세히 보여 준다. 매 행동의 결과를 짧은 문장과 체력·상태 변화로 즉시 표시한다. 전체 규칙 설명과 과거 로그는 접어 두고 필요할 때 연다. 고딕 분위기는 어두운 배경만으로 만들지 않고, 제한된 강조색과 일관된 타이포그래피로 만든다.
우선순위: 화면 뼈대 재구성 단계에서 적용.

2. Baldur's Gate 3 — 선택에 집중할 수 있는 전투 진행
확인한 사례: Larian의 전투 설계 글은 턴제에서도 반응성과 진행 속도를 중요하게 다룬다. 이전 동작 종료와 다음 동작 시작을 겹치고, 이동과 타격 애니메이션을 연결해 기다림을 줄이는 사례를 설명한다. 탐험 중 턴제 모드에 들어가 상황을 계획하는 기능도 소개한다. 이 글은 2020년 얼리 액세스 개발 자료이므로 현재 출시판의 모든 UI 세부사항에 대한 근거로 사용하지 않았다. 현재 공식 소개 역시 전략과 환경 상호작용을 강조한다.
적용 제안: 게임이 강제하는 처리들은 하나의 결과 흐름으로 보여 준다. 공격 확정 뒤 피해 계산·상태 적용·처치·확정된 보상 지급을 일일이 확인시키지 않는다. 화기 사용·회피 카드 선택·이동 방향 등 실제 선택이 있는 지점에서만 멈춘다. 애니메이션이 전략 판단을 가리지 않도록 빠르게 처리하고, 빠른 진행/연출 줄이기 설정을 둔다.
적용 경계: BG3의 자유 이동·행동 포인트·환경 규칙을 블러드본에 도입하는 제안이 아니다. 원래의 칸 이동과 카드 비용은 그대로 따른다.
우선순위: 상황별 행동 흐름 정리 뒤 자동 처리/결과 연출 단계에서 적용.

3. Solasta / Solasta II — 흩어진 정보를 표적 선택 시점에 모으기
확인한 사례: Tactical Adventures의 2025년 개발 글은 전작 정보가 로그·커서·적 초상 아이콘에 흩어져 접근하기 어려웠다고 직접 설명한다. 개선안은 표적을 고를 때 공격 정보를 알아보기 쉽게 보여 주는 것이다. 공식 예시 이미지에는 적 이름·체력·명중 정보와 그 이유가 함께 나타난다. 별도의 Dash 버튼 대신 목적지를 더블클릭하는 이동 조작도 설명한다. 당시 pre-alpha 예시이므로 출시판의 현재 상태를 단정하지 않는다.
적용 제안: 적을 클릭하면 현재 체력, 이미 공개된 특성, 공격 가능한 무기 슬롯, 카드 비용을 한 패널에서 확인한다. 출입구/칸을 고르면 경로와 지불할 카드, 도착 위치를 같이 보여 준다. 사용 불가 행동은 이유를 바로 제시한다. 예: ‘해당 슬롯에 카드가 놓여 있음’, ‘화기 소진’, ‘같은 칸의 적이 아님’.
적용 경계: 상대 행동 카드를 공개하기 전에 피해 결과를 확정적으로 예측하거나, 아직 공개되지 않은 보스 행동·임무 보상을 미리 보여 주면 안 된다. 공개된 사실만 표시한다.
우선순위: 지도 대상 직접 선택과 행동 미리보기 단계에서 적용.

4. Gloomhaven Digital — 카드 전술을 유지하면서 디지털 조작으로 바꾸기
확인한 사례: 공식 Steam 화면에는 중앙 전장, 왼쪽의 선택 카드 2장, 상단 행동 순서, 빛나는 이동 가능 칸, 하단 Undo / Confirm Movement / Skip Movement가 함께 보인다. 선택한 카드 면은 강조하고 사용하지 않는 면은 어둡게 처리한다. 공식 설명은 카드 선택과 격자 전술을 핵심으로 남긴다. 개발자 패치 기록에는 능력 선택 취소 지원과 표적 확정 화면의 선택 표시 수정이 있다.
적용 제안: 장치무기 슬롯과 손패를 ‘현재 행동을 만드는 도구’로 배치한다. 공격 기술/슬롯과 카드를 선택한 뒤 지도에서 적을 고르는 흐름을 한 곳에 묶는다. 선택 준비 단계에서는 취소·변경이 가능하게 하고, 실제 지불·공개·실행을 확정할 때 구분한다. 마지막 실행 전에 비용과 표적을 분명하게 보여 준다.
적용 경계: 숨겨진 카드 공개 이후의 되돌리기를 일반적인 Undo로 제공하면 원래의 정보 규칙이 달라진다. 취소는 아직 게임 상태를 바꾸지 않은 선택 준비에 한정한다. 원본 사진을 화면에서 제거해도 카드 전술 자체를 제거할 필요는 없다.
우선순위: 전투 UI 재구성 단계에서 가장 직접적으로 참고.

6. Wildermyth — 이야기를 조작 흐름의 일부로 보여 주기
확인한 사례: 공식 소개는 전술 전투와 이야기 선택의 결과를 연결한다. 공식 홈페이지의 게임 화면에는 큰 전장, 좌우 작은 캐릭터 정보, 이름과 단축키가 있는 하단 행동바가 보인다. 공식 도메인의 제작 문서에서는 이야기 대화를 화면 전체 또는 상황에 따라 하단으로 표시하고, 이야기 종료 전까지 이후 결과 처리를 기다리는 기능을 설명한다. 이 제작 문서는 공식 사이트가 연결하는 위키이지만 편집 참여가 가능하므로 개별 전투 수치의 최종 규칙 근거로 사용하지 않았다.
적용 제안: 새 임무 공개·NPC 대화·챕터 도입부는 게임 분위기의 별도 장면으로 보여 준다. 원본 카드 사진 대신 읽기 좋은 한국어 텍스트, 장소/화자 표시, 일관된 패널을 사용한다. 중요 선택이 없는 짧은 사건은 하단 알림으로 전달하고, 긴 장면만 읽기 화면을 쓴다. 지난 이야기는 공개된 내용만 일지에서 다시 읽게 한다.
적용 경계: 임무 해결 전에는 미래 결과·보상·분기 조건을 노출하지 않는다. 원문 이야기의 임의 각색으로 공식 내용을 바꾸는 방식도 피한다.
우선순위: 사진 제거 단계에서 텍스트 표시로 먼저 전환한 뒤 이야기 연출 단계에서 개선.

권장 화면 구조
상단: 챕터·현재 차례·사냥 트랙·체력·혈액의 메아리·화기 준비 상태.
중앙: 선택과 이동의 중심이 되는 지도/전장. 필요한 칸/문/표적 강조.
측면: 현재 선택 대상의 설명과 공개된 목표. 세부사항은 펼쳐 보기.
하단: 현재 행동에 필요한 무기 슬롯·손패·짧은 행동바. 소모품은 별도 작은 목록.
별도 창: 인벤토리·공개된 일지·설정·저장. 개발/검증 기능은 일반 플레이의 주 화면에서 분리.
이야기: 새 사건이 있을 때만 읽기 화면으로 들어갔다가 원래 지도 상태로 돌아옴.

작업 순서
1단계 — 원본 사진 노출 제거와 텍스트 정보 보존
  이야기 읽기·원본 확대·적/NPC/화기/무기 표시 등 사진이 플레이 화면으로 들어오는 경로를 막는다. 현재 공개된 사건의 이야기/규칙/선택지는 텍스트로 유지한다. 참고자료는 개발 확인용으로 보존하되 일반 플레이에서 호출하지 않는다.
  완료 조건: 일반 캠페인·검증 캠페인·기존 저장 불러오기에서 원본 사진 요청이 없으며, 이야기·현재 목표·선택지가 사라지지 않음.

2단계 — 탐험 화면의 뼈대 재구성
  지도 중심 HUD를 먼저 만든다. 상태·행동·목표·보조 정보의 위치를 고정하고 긴 웹페이지 스크롤을 줄인다. 탐험/전투/사냥꾼의 꿈/이야기 상태별로 필요한 정보만 우선 표시한다.
  완료 조건: 1366×768 기준 주요 위치와 현재 행동, 체력, 사냥 트랙을 스크롤 없이 읽을 수 있음. 넓은 화면과 좁은 화면에서도 지도 선택이 가능함.

3단계 — 지도와 상황에서 직접 행동하기
  칸·출입구·적·상자·등불·NPC를 클릭하면 현재 가능한 행동이 열리게 한다. 이동 경로와 비용, 무기 슬롯 선택과 카드 지불을 가까운 위치에 둔다. 사용 불가 이유와 선택 취소를 제공한다.
  완료 조건: 이동/상자/적 공격의 대표 동작에서 목록창과 드롭다운을 찾는 조작이 줄어들고, 규칙상 다른 카드 선택과 다른 표적 선택이 모두 가능함.

4단계 — 전투 선택과 강제 처리 정리
  선택한 공격·슬롯·카드·표적을 한 화면에서 확정한다. 화기·회피·방어·넉백 방향·카드 버리기 등 실제 선택을 남긴다. 피해·상태·처치·확정 보상 등 계산은 연속 결과로 전달한다. 적 행동 공개 시점을 원래 규칙과 동일하게 유지한다.
  완료 조건: 기존 무기 15종과 화기 8종의 기능이 남으며, 회피/방해/보스 행동/보상 창에서 선택할 기회가 건너뛰어지지 않음.

5단계 — 이야기·일지·보상 경험 정리
  도입부, 공개된 임무 이야기, NPC 대화, 챕터 종료를 텍스트 장면으로 통일한다. 현재 목표 추적과 지난 사건 일지를 분리한다. 보상은 실제 획득한 시점에 처음 표시한다.
  완료 조건: 읽기 화면을 닫아도 지도와 선택 상태가 유지되고, 아직 공개되지 않은 카드·보상·분기 내용은 탐험 HUD/툴팁/일지 어디에도 나타나지 않음.

6단계 — 독자적인 시각 자산과 반응 연출
  고유한 지도 배경, 적/사냥꾼 표식, 무기·화기·소모품 아이콘을 같은 스타일로 제작한다. 이동·공격·피해·등불 복귀에 짧은 시각/음향 피드백을 준다. 연출 속도, 글자 크기, 키보드 조작, 색 이외의 상태 구분을 추가한다.
  완료 조건: 사진 재사용이 없으며 칸·문·등불·상자가 알아보기 쉬움. 빠른 연출/연출 줄이기 설정에서도 규칙과 선택 순서가 같음.

각 단계의 검증 기준
- 게임 규칙과 이전 저장 호환성 회귀 검사는 유지한다.
- 검증용 장비는 조작 흐름·렌더링 점검에 사용하고, 실제 전략과 밸런스 확인은 일반 장비로 별도 수행한다.
- 이동 시작→출입구 통과, 상자 획득, 일반 적 공격, 보스 회피 선택, 등불 복귀, 이야기 읽기→지도 복귀를 대표 동작으로 고정해 조작 수를 비교한다.
- 조작 수뿐 아니라 잘못 선택한 횟수, 목적지/비용을 이해한 정도, 다음 행동을 찾는 시간을 함께 본다. 빨라졌다고 전략 선택을 자동으로 없애면 목표를 달성한 것이 아니다.
- 색상 변경이나 카드 패널 장식만으로 RPG 경험 개선이 끝났다고 판단하지 않는다. 화면 뼈대와 행동 흐름을 먼저 개선하고 시각 자산은 그 위에 올린다.
