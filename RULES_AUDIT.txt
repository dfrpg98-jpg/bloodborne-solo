블러드본 개발판 v0.6.1 규칙 구현 검토
검토일: 2026-10-11 KST
검토 대상: 사용자 프로젝트 bloodborne-solo의 v0.6.1 수정본
기준 자료: 사용자 제공 블러드본한국어규칙서_압축.pdf(28쪽), campaigns/long-hunt/data.json, components/cards.json

판정 기준
- 구현: 현재 hunt.html의 1인용 챕터 1에 실제 엔진과 사용자 조작이 연결되어 있음.
- 부분: 상태/자료 또는 일부 절차만 존재하며 전체 규칙 실행은 되지 않음.
- 미구현: 실행 경로가 없거나 명시적으로 거절함.
- 확인된 오류: 제공된 규칙과 현재 동작이 충돌하며 코드 또는 명령 재현으로 확인함.
- 해석/한계: 적용 범위 밖의 자료, 임시 수치, 자동 판정하지 않는 선택 등을 확정 오류와 구분함.
- P1: 현재 1인용 챕터 1 플레이에서 규칙상 가능한 선택을 막는 문제.
- P2: 후속 챕터/일반 규칙 확장 또는 임시 시험에서 필요한 기능.
- P3: 자료 표시, 안내, 개발 기록 정리.

중요 결론
v0.6.0에는 새 사냥 설정의 시작 칸 선택이 이미 있었지만, 첫 방문에 자동으로 중앙 칸에서 사냥을 생성하여 선택 기능을 발견하기 어려웠다. v0.6.1에서는 첫 실행에 설정을 먼저 열고 중앙 등불 타일의 세 칸을 도식에서 선택하도록 보완했다. 중앙 등불에서 안개 안 칸으로 순간이동하는 선택과 폐가의 구조/소모품 결합 상호작용도 고쳤다. 다음 챕터 자체는 미구현이므로 모든 챕터 시작마다 선택하는 흐름까지 구현됐다고 볼 수 없다.

1. 현재 챕터 1의 우선 점검 사항

A01 | 해결 | 시작 위치 선택의 노출 | 규칙 10쪽
근거: hunt.html setupDialog, hunt-app.js setupRequired/openSetup/confirmSetup, start-placement.js BBStartPlacement.mount/update, chapter-engine.js create(startSpace).
선택값 left/center/right는 실제 초기 위치와 저장 setup에 반영된다. 첫 방문에 시작 칸 도식 선택을 먼저 표시하고 새 사냥에서도 같은 선택을 사용한다. 기존 정상 저장이 있으면 그 위치로 이어한다.

A02 | 해결 | 중앙 등불에서 안개 내부로 순간이동 | 규칙 10쪽 타일 인쇄 효과, 24쪽 안개
수정 전 근거: hunt-engine.js teleport()는 목적지 node.lamp만 허용; INTERACT도 node.lamp만 검사. hunt-app.js 상호작용 목적지 목록은 lamp만 표시. 안개 타일 등불은 nodes()에서 lamp=false가 된다.
초기 감사에서는 안개 타일의 모든 칸이 거절됐다. 규칙은 중앙 등불 칸에서 상호작용할 때 아무 정상 등불 또는 안개 내부의 아무 칸으로 갈 수 있게 한다. 보상 랜턴/소모품 순간이동의 목적지 확대와는 별개이다.
자연 재현: E.create(90, 'burial', 1, null, 'hunter-pistol', 'center', {campaign:true})에서 tests/fixtures/chapter-one-commands.json의 첫 17개 명령 재생. 사냥꾼=tile-14:center, fog=['tile-04']. INTERACT {cardId:hand[0].id,lamp:'tile-04:left'}.
수정 근거: hunt-engine.js centralLampDestinations/teleport/INTERACT/collectLoot와 hunt-app.js renderDecisions의 tileLamp 목록. 해당 명령으로 왼쪽 칸에 이동하는 것을 재확인했고 tests/audit-fixes.test.cjs에서 안개 세 칸 이동/저장 재생, 일반 칸 거절, 보상 랜턴의 망가진 등불 거절을 검증했다.

A03 | 해결 | 폐가 생존자 구조와 소모품의 한 번 상호작용 | 규칙 16쪽
수정 전에는 엔진이 mission:'rescue'와 lootCount를 함께 받을 수 있었지만 UI 버튼이 분리되어 있었다. hunt-app.js renderDecisions의 '생존자 구조도 함께 선택' 체크박스와 interact 처리로 카드 1장에 소모품 수와 구조를 함께 전달한다. 적의 반격을 먼저 처리한 뒤 소모품과 구조를 해결한다.
검증: tests/audit-fixes.test.cjs의 자연 명령 체크포인트에서 소모품 2개와 구조를 동시에 선택하여 mission_survivor로 진행하고, 카드 비용/소모품 수량/정확한 저장 재생을 확인했다. 일부만 선택하는 단독 구조/소모품 선택도 남겨둔다.

A04 | P1 | 성배 교단 예배당 소모품 교환 | 규칙 16쪽 상호작용 + 제공 tile-07 효과 | 미구현
근거: campaigns/long-hunt/data.json tile-07.rules는 상호작용 때 소모품 1장을 사용하여 유지 1개 획득. hunt-engine.js interactionOptions()의 workshop=false; INTERACT의 a.exchange는 '아직 연결 전'으로 거절.
이 타일은 챕터 1 무작위 후보에도 포함되므로 후속 챕터만의 문제가 아니다. 소모품 선택과 버림/유지 상한 처리를 연결해야 한다. 현재 보호된 거절이므로 무단 소비 오류는 없다.

A05 | P1 | 골수 가루의 보상 준비 | 규칙 17쪽 보상 준비 + 제공 소모품 효과 | 미구현
근거: components/cards.json:90~103 bone-ash, runtime='pending', effects.readyReward=true. hunt-engine.js consume()는 runtime='playable'만 허용. rewards-engine.js:210 ready()는 존재하나 useConsumable()에 연결되어 있지 않다.
이제 챕터 1에서 소진되는 보상을 획득할 수 있으므로 현재 1인용 플레이에서도 빠진 기능이다. 이름/데이터 등록과 보상 모듈 단위 테스트는 소모품의 실제 사용 구현을 뜻하지 않는다.

2. 전체 규칙 대조표 (현재 1인용 챕터 1 기준)

규칙 8쪽 - 체력 6, 기본 네 유형 각 3장, 시작 무기 면 선택: 구현. hunt-engine.js create() 12장/체력 6, hunt.html face 선택. 장송의 칼날 양면은 제공 자료대로 연결. 전체 사냥꾼/다른 장치 무기 선택은 미구현(허용 weaponId='burial'만). 제공되지 않은 무기 효과의 임의 생성은 하지 않음.

규칙 9쪽 - 업그레이드 시장 4장, 덱/소모품/트랙 준비: 구현. hunt-engine.js create()가 업그레이드 60장에서 시장 4장, 소모품 덱 36장, track=1을 생성. 기본 스탯과 업그레이드 덱 분리/공급 보존을 assertState와 테스트로 확인. 소모품 37번째인 초대장은 기존 사용자 지시로 제외한 의도적 예외.

규칙 10쪽 - 중앙 타일/시작 칸, 적 3종의 각 면과 슬롯 무작위, 필수+무작위 타일 덱: 챕터 1 구현. chapter-engine.js create()가 필수 네 타일+무작위 두 타일, 적 양면/세 슬롯을 섞는다. 시작 칸은 A01 해결. 챕터 2/3 특수 준비 카드 17의 고정 배치와 추가 타일 준비는 미구현.

규칙 12~13쪽 - 임무 조건부 공개/계몽/사냥 승패: 챕터 1 구현. mission-engine.js:16,57,100,199의 공개/처치/구조 분기와 완료 카드 계몽 계산. 캠페인 참조자료의 reveal 배열을 무조건 공개하지 않는다. track 마지막 라운드 종료의 실패와 챕터 완수 후 꿈의 성공 처리 존재. 챕터 2/3 임무는 미구현.

규칙 12쪽 - 도입부/임무 이야기 읽기: 부분 UI. 도입부 서사는 campaign 데이터 preface에 있고 별도 campaign.html 자료집에서 볼 수 있다. hunt.html의 시작 설정/사냥 화면에는 도입부를 보여주지 않는다. 공개 임무는 rules 위주이며 이야기는 접힌 원본 사진에서 읽게 된다. 룰 자동화 오류보다 서사/안내 누락(P3).

규칙 14쪽 - 행동 비용/최대 2칸 이동/중도 정지/이동 중 다른 행동 금지: 구현. hunt-engine.js MOVE,STEP,STOP_MOVE와 phase 검사. 다른 피규어가 이동을 가로막지 않는다. 추가 이동 카드/소모품은 실제 이동/추격 절차에 연결.

규칙 14쪽 - 추격: 구현. stepHunter()가 나온 칸/타일의 적을 기록하고 continuePursuit()가 실제 이동 경로를 따라 처리. 재앙의 야수 2칸 예외 연결. 추격과 일반 활성화는 구분.

규칙 14~15쪽 - 출입구 맞춤/회전/발견 타일 의무 진입/타일에 적과 소모품 먼저 배치: 구현. chapter-engine.js graph/exits/placementOptions와 hunt-engine.js explore/placeTile/finishSpawns. 양쪽 출입구가 있어야 인접. 피규어를 먼저 배치한 뒤 사냥꾼 진입.

규칙 15쪽 - 모든 출입구 차단 타일 다시 뽑기: 구현하되 마지막 타일 예외를 적용한 해석 존재. requireOpen는 남은 덱 여부에 따라 결정되어 마지막 타일은 지도 봉쇄 배치를 허용한다. 인쇄 규칙에는 마지막 타일 예외가 별도로 기재되지 않았지만 더 뽑을 타일이 없다는 상황이 있다. 이를 확정 오류로 판정하지 않음. 필요하면 플레이 규칙을 추가 확인할 항목.

규칙 15쪽 - 적 네 피규어 공급/가장 먼 피규어 재사용: 1인용 구현. hunt-engine.js farthest/finishSpawns는 거리 비교, 동률 선택, 5번째 생성 방지. 임무 적은 보존하도록 일반 재배치 후보에서 제외한다. 다인용 '모든 사냥꾼으로부터 거리'는 미구현 범위.

규칙 16쪽 - 소모품/임무 상호작용 및 적의 선행 반격: 구현. nextInteraction()이 같은 칸 적을 먼저 해결, 공격/회피 금지, 죽으면 효과 미실행. 한 번에 복수 요소 결합은 A03 UI 수정 완료. 성배 교단 예배당의 교환은 A04 미구현.

규칙 16쪽 - 변형/꿈/공격: 구현. 카드 비용, 슬롯 전체 비우기 및 면 뒤집기, 아무 칸 꿈 입장, 같은 칸 적 공격과 빈 슬롯 조건을 엔진에서 강제. 카드 효과에 따른 무료 변형/도약/슬롯 비우기도 연결.

규칙 16쪽 - 적 활성화 범위/슬롯 순서/적 이동/공격: 1인용 구현. eligible(),activateEnemy(),runEnemyMove()가 같은/인접 타일, 슬롯 우선, 경로 동률 선택, 이동 후 같은 칸이면 전투. 활성화 도중 새로 출현하는 적도 다시 평가한다. 다른 사냥꾼과 같은 칸에 있는 적의 이동 제한/다인 공격은 다인용 미구현 범위.

규칙 17쪽 - 소모품 시점/사용 후 버림/덱 소진 재구성: 제공 19종 중 16종 실제 실행. 골수 가루 미연결(A05), 사냥꾼의 종은 다른 사냥꾼이 없어 1인용에서 사용할 수 없는 의도적 제한, 초대장은 사용자 요청에 따라 제외. 이를 모두 같은 '기능 오류'로 합산하면 부정확하다.

규칙 17쪽 - 보상 소진/꿈 준비/도구2+문자2 한도/화기1: 챕터 1의 6종 보상과 획득 장총에 구현. rewards-engine.js supported/definitions/grant/dispatch/onDream. 초과 장비 보관 선택 존재. 전체 보상 32종 중 나머지 26종은 아직 실제 획득/효과 연결이 없고, 일부는 원문 자체가 '사용불가'인 임무 물건이다. 다인 보상 전달은 미구현.

규칙 18쪽 - 새 라운드 트랙 전진/원하는 손패 버림/3장 보충/덱 재구성: 구현. nextRound,advance,REFILL,draw와 hunt-app.js refill 체크박스. 손패가 이미 3장 초과면 억지로 버리게 하지 않음.

규칙 19~20쪽 - 공격 카드 즉시 효과/공용 행동덱/회피/속도 순서/동시 효과: 제공 실제 적3종6면에 구현. place/commitAttack/reveal/canDodge/resolve와 enemy-deck.js 3기본+2특수+1능력. 전용 능력은 기본 공격과 구분, 실제 카드에 적힌 동일 속도 선행 처리 포함. 즉시/유속 능력, 추가 행동 공개, 다단 타격을 별도 연속 상태로 해결.

규칙 21쪽 - 방해/기절/유지 상한/동시 처치/빈 슬롯 없음: 구현. resolve/pendingCombat/takeDamage/enterDream. 동시 처치 시 유지 전부 잃음, 유지 3개 상한. 피해를 막아도 이미 해결한 카드 즉시 효과를 되돌리지 않음.

규칙 21쪽 - 독/발광: 일반 지원은 부분. 상태 보유/차례 끝 독 피해/발광 공격 피해 +1/꿈 제거/소모품 제거/면역 데이터는 존재. 그러나 hunt-engine.js enemyDef convert()와 resolve()에는 독/발광 공격에 의해 상태를 부여하는 처리가 없다. 현재 제공된 챕터1 적6면에는 해당 상태 키워드가 없으므로 현재 챕터1 플레이 오류라고 주장하지 않음. 후속 적/NPC 연결 시 필요(P2).

규칙 21쪽 - 일반/특수 칸에 있는 흰 배경 전용 능력: 일반화 미구현. enemyDef는 현재 실제 적의 기본/특수를 모두 type='attack'으로 변환하고 개별 능력 코드를 실행한다. 현재 제공 적6면에는 이를 요구하는 기본/특수 능력 카드가 없어서 현 챕터1 누락 오류는 아님. 후속 자료 연결에 필요한 기능(P2).

규칙 23쪽 - 보스: 임시 시험 일부 구현. kill()은 1페이즈 체력 소진 시 전치유, 2페이즈 전환, 초과 피해 폐기, 이미 공개된 이번 전투 공격 유지. 하지만 독립된 1/2페이즈 행동덱이 없고 reveal()은 일반 공용6장덱을 사용한다. 실제 성직자 야수 캠페인 출현/실제 행동도 미연결. 임시 시험을 정식 보스 규칙 구현으로 보지 않는다(P2).

규칙 23쪽 - NPC 적: 미구현. 현재 temporary-components.js의 iosefka는 비전투 치유 상호작용 시험이며, 규칙서의 적대 NPC 카드/플레이어수별 면/토큰 적 피규어 대체와 다르다. 사용자 허용 임시 효과임을 UI에 명시하지만 적대 NPC의 일반 실행 경로는 별도 필요(P2).

규칙 23~24쪽 - 꿈 업그레이드/12장 유지/덱 재구성/치유/다음 라운드 등불귀환: 구현. enterDream,PICK_UPGRADE,REPLACE_UPGRADE,finishDream,RETURN. 각 구매 뒤 시장 즉시 보충, 신규 카드 미채택도 허용, 무기 면 선택, 망가진 등불 제외.

규칙 24쪽 - 지도 초기화: 현재 챕터1 일반/임무 적 및 소모품 구현. 임무 적 우선, 가까운 일반 출현, 부활 토큰 보충, 면/슬롯/행동덱 유지, 마지막 칸 재초기화 구현. 보스 일반 규칙은 부분: resetMap()이 전체 적을 지우고 spawnProvisional()로 시험 보스를 중앙 등불에 재생성한다. 이미 움직인 보스는 현재 칸에 남아 체력만 회복해야 하므로 시험 한정 불일치. 2페이즈 상태는 유지한다(P2).

규칙 24~25쪽 - 안개 출입/파괴 등불/일반 적 제거 및 출현 금지/분리 활성화/완수 후 해제: 챕터1 구현. mission-engine.js encounter/complete와 fogged, hunt-engine.js stepHunter/teleport/moveOptions/eligible/finishSpawns. 중앙 등불의 안개 안 목적지 예외는 A02 수정 사항.

규칙 24쪽 - 교활하고 잔혹하게: 부분 수동 진행. 경로/같은 순위 활성화/피규어 공급 동률을 플레이어가 선택하게 한다. 가장 불리한 선택을 자동 계산/강제하지는 않는다. 최적/최악 전략 계산을 규칙 자동화가 완료된 것으로 보지 않음.

규칙 25쪽 - 챕터 완료 꿈 및 보관: 챕터1 완료 꿈/성장/소모품/화기/보상/계몽의 JSON 저장 구현. 다음 챕터 준비, 새로운 적 면/슬롯/덱/트랙 구성, 보관한 장비 교체, 챕터 2/3 진행은 미구현. rewards-engine.js betweenChapters()의 phase 이름은 엔진 assert/dispatch에서 도달 가능한 상태가 아니다. 승리 상태는 over이고 그 상태에서는 필수 보상 선택 외 명령을 거절한다.

규칙 26쪽 - 순간이동이 이동으로 간주됨: 구현. teleport()가 위치 변경 후 onMovementEnd를 실행, 호위 토큰은 이동 조건 평가 전에 집으로 돌아감. 꿈 귀환은 별도 RETURN 절차. 추격은 실제 이동 행동에만 적용.

3. 자료/안내와 실제 구현의 불일치

P3 - campaigns/long-hunt/data.json의 chapterSetupRules.scopeNote와 일부 components/cards.json.runtime='reference' 문구는 과거 자료 수집 때의 상태다. 현재 챕터1 임무/6종 보상은 실행되는데 자료집에는 미연결이라고 표시될 수 있다. 소스 전사문/사진 기록은 보존하되 현재 실행 상태는 별도 메타데이터로 표시하는 것이 정확하다.
P3 - 추가 화기 세 종(루드비히 장총, 교단 연발총, 화염방사기)은 data.js:176~182의 기존 사용자 승인 임시 단총 효과를 공유한다. 획득/보관/소진 기능은 있지만 실제 개별 화기 능력 구현은 아니다. 현재 UI도 임시 대체를 표시한다.
P2 - 2~4인 협동, 턴 순서 선택, 다른 사냥꾼 대상 효과, 전리품 전달, 플레이어수별 준비/토큰/보스체력/NPC면은 미구현. 현재 assertState가 정확히 한 사냥꾼만 허용한다. 온라인 기능만의 문제가 아니라 게임 규칙의 다인 실행도 아직 없다.

4. 검증 및 한계

기존 전체 테스트를 실제 실행: 171개 통과, 실패/건너뜀 0개. 실행 런타임은 번들 Node, 명령은 node --test tests/*.test.cjs.
tests/campaign-playthrough.test.cjs는 seed 90의 실제 122개 명령으로 계몽[7,15] -> 최종[4] 완료, 성장/소모품/보상/화기/계몽 보존, 최종 꿈, 정확한 저장 재생을 확인한다.

새로 짚은 A02/A03은 이전171개 테스트가 통과해도 놓칠 수 있었던 UI/선택 누락이다. 수정 후 추가 회귀 테스트 3개를 실제 실행하여 전부 통과했다. 테스트 수가 전체 규칙 완성을 증명하지는 않는다. 최종 전체 테스트 수와 브라우저 검증은 패키지의 VERIFICATION.txt를 참고한다.

6. 지도 도식 교체와 대조 범위

assets/tiles/tile-01.svg~tile-20.svg에 20개 지도를 직접 만든 SVG로 제공한다. assets/tiles/index.html은 전체 도식 목록, legend.svg는 기호 설명이다. tile-geometry.js와 scripts/generate-tile-diagrams.cjs에서 도식/클릭 영역의 같은 좌표를 생성한다.
독립 지도 감사에서 원본 사진20개와 실제 렌더링한 SVG20개를 대조했다. 확인한 논리 구조는52칸,47출입구,등불7개,소모품 위치12곳/초기토큰14개,적출현17곳(금색6/적갈색5/보라6)이다. 칸별 소속/종류/수량과 내부 인접/출입구 방향을 대조했다. 마당 등불은 W/E/S 세 출입구이며 N 출입구가 없다. 10번 타일의 중앙 막힌 건물과 양측 돌아가는 칸도 유지한다.
경계선의 비율과 기호 픽셀 위치는 촬영 원근을 제거하여 전사한 좌표이므로 물리 치수/원사진 픽셀의 완전 일치를 인증하지 않는다. 검증하는 동일성은 게임상 칸 구조·연결·출입구 소속·기호칸/수량과 클릭 좌표의 일치이다. 배경 그림/장식 벽/사진 질감은 넣지 않았다.
지도·배치 미리보기·타일 자료실은 새 도식을 사용한다. 새 배포ZIP에는 지도 타일 사진을 제외하며, Desktop에 사용자가 제공한 원본 자료는 보존한다. 다른 카드 사진은 이번 지도 사진 교체 범위에 포함되지 않는다.
지도 감사의 별도 테스트5개는 좌표 구멍/겹침,경계 인접,4방향 회전,SVG 기호 데이터,사진/래스터 참조 부재를 검증했다.
